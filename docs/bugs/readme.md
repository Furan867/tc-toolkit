# bugs

未修/在查的 bug，一个 bug 一个文件。修好之后**不删文件**，改成把 `状态` 那行写上修复提交，
所以这个目录同时是「修过什么、怎么确认的」的记录。

`archive/` 放「已修且不再需要复现」的记录（修复已稳、或现象已无法重建）；仍在被引用的修好文件
留在本目录，方便 `docs/` 里的指针继续指向它。

## 每个文件长什么样

```text
- 状态：未修 / 已修（commit）/ 不修（非我方 bug 或参考侧不可复现）
- 影响：哪些语料 / 哪些构造
- 现象：可观察到的错误，带数字
- 判据：怎么算修好了（跑什么、看什么）
- 已确认：带出处的硬事实（命令 + 输出片段）
- 已排除：试过但确定无关的方向，各附一句为什么不成立
- 下一步：
- 复现：命令
```

「已排除」这一节比「已确认」更值钱——它防止下一个人（或下一个 LLM）把同一条死路再走一遍。
