# 2026-10-13 转发层补记 flags / Result 全 5 字段

## 为什么

待办要求：`flags`（游戏传入值未知）与 `out[3]/out[4]` 从未落盘，需要一行把
src / 产物 / flags / 字段串起来（带 sha256）；记录失败必须静默跳过。

## 决定

- **新开 `work/hook/manifest.tsv`，不往 `hook.log` 里塞字段**：`hook.log` 的行格式已被
  `bench_rewrite`（数新行判断编译是否触发）与 `watch_freq`（提 `rewrite=` 行）解析，
  语义是「配置与流程事件」。
- 列（TSV，首行表头）：`seq time flags src src_len src_sha256 out out_len out_sha256 r0 r1 r2 r3 r4`。
- 落在 `work/hook/`，清空时机与 `.si`/`.bin` 对齐：`purge_captures` 的扩展名清单加 `.tsv`。
- 写在 `optimize_inplace` **之后** → `r2` 记的是改写器更新后的最终锚点。
- sha256 走系统 BCrypt（构建加 `-lbcrypt`）：`optimize.log` 的指纹是 Python `hashlib` 算的，
  两边必须逐字符可比。
- `dump()` 改为返回「是否真的落盘」：没落盘就在 manifest 里写 `-`，不指一个不存在的文件。

## 验证（离线，不动游戏目录）

把 `build/compile_hook.dll` 与游戏目录的 `compile_real.dll` 复制到暂存目录
（转发层「按自身模块路径找同目录 `compile_real.dll`」的逻辑即成立），
在独立进程里调 `compile()` 三次：空源码 flags=0、样本 flags=0、样本 flags=7。

| 检查项 | 结果 |
|---|---|
| flags 入库 | 0x0 / 0x0 / 0x7 如实记录 |
| src sha256、长度 | 与 Python `hashlib` / `len` 一致 |
| 产物 sha256、长度 | 与 `hook_out_NNN.bin` 的 hashlib / `stat` 一致 |
| `r0..r4` | 与调用方缓冲逐字一致（`r0` = 缓冲总长含 8 字节头、`r2` = 0x212F 空源码锚点） |
| `r3` / `r4` | **被写成 0**（缓冲预填 0xCC 哨兵）→ 是编译器写的，不是残留 |
| 清空语义 | 连续两次加载，`manifest.tsv` 都从 001 重新开始 |

备份：加载转发层会按设计清空工作区，先把 `work/hook` + `work/opt` 归档到
`%TEMP%\tc_hook_backup_20261013-215710.7z`（3.3 MB，365 个捕获文件）。
