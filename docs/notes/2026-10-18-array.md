## 结论（四条，各带判据）

| 结论 | 判据（怎么验的） |
| --- | --- |
| 值是**指向载荷的指针**，载荷前 8 字节是头，`头 >> 16 == n` —— 与 `Str` 同一套 Nim 布局 | `layout` 探针：`array(<U8>,4)` → `p=0x4002540bf008`、`load(<U64>,p-8)=262149=0x40005`（`4<<16 \| 5`）、`load(<U64>,p)=740365835=0x2c21160b` = 字节 `11,22,33,44` 小端拼成 → 载荷紧跟头 |
| 元素按 **U-L1 字节步长**紧密排列：`<U8>` → 1、`<Int>` → 8 | `layout`（U8 那 4 个字节连续）、`int8`（`array(<Int>,3)`：`load(<U64>,q-8)=196615=0x30007`，`q+24` 是数组外的下一个 u64） |
| 载荷**零初始化**（不写就读得到 0） | `zero` 探针：`array(<U8>,4)` 读 → `0,0,0,0`；`array(<Int>,3)` → `0,0,0` |
| `.len()` = `load(u64, p-8) >> 16`，`size(arr)` = **64**（bit，= `Array` 的存储宽度 8 字节，与 `storage_bytes` 一致） | `ptrlen`：`{a.len()}` → `4`；`size`：`size(a[0])` → `8`（U8 的 bit 数）、`size(a)` → `64` |

未验（明确标「未验」，不许猜）：**越界**（`a[4]` / `a[-1]`）—— `oob` 探针参考侧 `rc=0` 但 `blob=0 B`
（编译被拒），拿不到运行期行为。语料不越界，没做。头的**低 16 位**（观察值 `4→5`、`3→7`）没解出来，
但消费者只读 `>> 16`，所以按 0 写。

**能不能只用静态缓冲**：能，而且实测够用。参考在**堆**上分配（每次调用新缓冲，首址固定
`0x4002540b...`），我们改成**每个调用点一枚私有全局**（头 + 零载荷，加载期零初始化）。
「每次调用重新零初始化」这条差异**未在语料上验**：语料里 `array()` 都在「建表」函数里、每次运行只调一次
（`grep -n "array(" corpus/src/*.si` 的 15 处全在 `run_sim` 体或只跑一次的函数里）。

### 为什么「可装配数」没上升（这是本轮最重要的发现）

`array` 与裸块只是链条上的**两环**，后一环被别的缺口接住。15 份的下一道（本次实测，
`work/tmp/arraytask/target.tsv` 与 98 份报告）：

| 下一道缺口 | 份数 | 语料 |
| --- | --- | --- |
| `random()` 未实现 | **12** | 098、149、159、162、163、164、165、167、168、171、172、174 |
| 闭包捕获：根体的 `var` 被**顶层 def** 里的嵌套 def 引用（按调用点解析拿不到） | 2 | 084、096（`instructions @ 1083`/`1720`） |
| 根体里的名字 `counter` 未定义 | 1 | 147（`@ 1044`） |
| 空数组字面量 `Arr[U8] []` | 1 | 157（`@ 3848`） |

即：`array` 那 15 份**没有一份**是只差 `array` 的 —— 12 份还差 `random`（已知的 32 份大票），
2 份还差闭包捕获（已知的 12 份票，要改 ABI），1 份差 `counter`，1 份差空数组字面量。
三处都不是本任务范围（`random`/闭包/空数组字面量各有独立票），**没有顺手修**。
报告口径里 `Unsupported: array` 这一类已归零，改为 `random +12`、`instructions 2`、`counter 1`、
`空数组字面量 1`。

## 风险

- 每次 `array()` 都复用同一枚全局（参考每次新分配）：只对「同一调用点被跑多次且依赖零初始化」的源代码有差异，
  本语料没有这种代码，但**没验**。
- 运行期对照只覆盖了 `rw` / `rt` 两个片段（常量下标、运行期下标、`.len()`、多个数组并存）；
  `size(arr)` 的 **64** 是从参考探针读出来的，我们的 `size()` 走编译期那条，语料里的 `size(err)` 用法没动。
