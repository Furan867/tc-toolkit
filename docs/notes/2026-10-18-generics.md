# 泛型实例化（`@Size` / `@Type` / `@Any`）实现 —— 17 份 `编译期类型参数` 归零，可装配 70 → 75

日期：2026-10-18 · 写区 `simplexc/lower/**`（未动前端）· 片段与探针在 `work/tmp/generic/`。

## 1 那 17 份要的是 `@Size` 的哪一面

17 份的失败点全部是同一对标准 def（98 份语料每份都带，只有这 17 份**真调**了 `get_ram_value`）：

```simplex
def get_ram_value(label: Str, address: Int, size: @Size) @Size {
    if label == 'Program' { return load(type_of(size), #DATA_… + (256 - ((size(size) + 7) / 8)) - address)) }
}
def set_ram_value(label: Str, offset: Int, value: @Type) None { … }
…
let instruction = get_ram_value("Program", cycle, <U8>)      # 100/102/104/106/157
U32 get_ram_value("Register File", dest * 4, <U32>)          # 147/149/159/162…174
```

所以这条缺口要的是「`@Size` 的四件事」，不是别的：

| 要的 | 语料里的形态 |
| --- | --- |
| 类型实参写在**实参表里**、且不占运行期槽 | `get_ram_value(a, b, <U8>)` 只有 2 个值实参 |
| `size(类型参数)` 折常数（位） | `size(size)` → 8 / 32 |
| `type_of(类型参数)` 当**类型实参**用 | `load(type_of(size), p)` |
| **返回类型**写成类型参数 | `) @Size` |

`set_ram_value` 在 17 份里**一次都没被调用**（按需 lowering 不会发它），所以 `@Type` 的值形实参
（`size(value)` + `store(…, value)`）这一面语料没考到。

## 2 参考侧补的一条实验：返回类型 `@Size` = **绑定的那个类型**（原来只有「未验」）

`work/tmp/generic/g_rettype2.si`（`def gtr(s: @Size) @Size { return 0x123456789 }`，
三处 `store(Ptr 0x2000/0x2008/0x2010, U64 gtr(<U8>/<U16>/<Int>))`）→ `refc.py` 出产物，看追加区末尾：

```text
b9 89 00 00 00          mov ecx, 0x89          # <U8>  → 截到 8 位
b9 89 67 00 00          mov ecx, 0x6789        # <U16> → 截到 16 位
48 b9 89 67 45 23 01    movabs rcx, 0x123456789 # <Int> → 不动
```

⇒ `@Size` 在返回位置**就是该实例绑定的那个具体类型**（不是「未定的 64 位」）。我们的实现取
「签名里第一个类型参数的绑定」—— 语料里每个 def 只有一个类型参数；多类型参数这个形状**未验**。

（`g_rettype.si` 是同一件的反证：`load(type_of(s), …)` 读的宽度也跟绑定走，`<U32>` 出来是一条
`mov edx,DWORD PTR [rcx]` + 一次 `shl 32/shr 32`（= 零扩展成 64）。）

## 3 实现要点（`lower/lower.cc` / `lower.hh`）

1. **`Inst`（每个实例一份）**：类型参数名 → 具体类型、**运行期形参表**、形参 ← 实参下标映射、
   规范化串 `sig`。函数签名只能按实例定，因为类型实参的两种写法（`g(a,<U8>)` 不占槽、
   `g(load(<U8>,p))` 值本身就是实参）**运行期参数个数不同**。
2. **缓存键与函数名**：接口 §1 的 `实例化名 = "<函数名>$<实参规范化串>"`。`sig` 形如
   `str,int,@u8`（类型参数带 `@` 前缀），值形另加 `#v` 后缀；函数全局名 = `名字$sig`（再有捕获则是
   `名字$sig$c0`）。**非泛型 def 的 `sig` 是空串** ⇒ 名字、键、参数表逐字节不变（见 §5 判据）。
3. **`size(x)` / `type_of(x)` 只在类型参数上成立**：都先查本实例的 `ty_binds_`（类型参数不占运行期槽，
   所以它在作用域里**没有变量绑定**，`static_type` 查不到），再退回 `static_type`。`size` 的单位是位
   （`storage_bytes × 8`）；枚举在 `size()` 上仍报 `Unsupported`（U-L5 的 1/2 字节档与承载宽度不是一回事，
   不静默给 64）。
4. **`load(type_of(x), p)`** 是 `load` 的**第二种形态**（`type_args` 为空、实参 2 个）—— 前端把
   `type_of(size)` 解析成实参表里的一个 CallExpr，位置信息在 `CallExpr` 里已经丢了（`type_args` 与
   `args` 分开存），所以类型实参只能按**声明序**与类型参数一一对应。
5. `pick_def` 只对**泛型候选**加了「实例化失败就跳过这个候选」；非泛型候选那条老路径一行没改。

## 5 遗留风险与下一层缺口

1. **`@Type` 的「值形实参」语料没考到**（`set_ram_value` 无人调用）。实现上按「值本身是实参、类型由它推出」
   发一个运行期槽（`#v` 实例）。事实表里 `gs(load(<U8>,p8))` 那条实测只证明 `size()` 会折成 8，
   **没有**证明那个值真的进过函数体 —— 这一面仍属未验。
2. **类型实参的位置信息在前端丢了**（`CallExpr` 把 `type_args` 与 `args` 分开存）。语料只有「类型参数在
   尾部」这一种形状，按声明序绑定够用；混合形状（`f(<U8>, x, <U16>)`）按现在的实现会绑错位置。
   要修得动 `frontend/`（本轮禁区）。
3. **嵌套泛型 `<@Type>` 照抄参考的「不透明传」没做**：`ginner(<@Type>)` 现在仍走 `ty_of_ref` 的
   `Unsupported`（参考里 `size()` 塌成 −1）。98 份里没有这种形状，不猜。
4. **`hex` 是 12 份的新墙**（`stdlib_prefix.si:1110-1234` 的 `str`/`bin`/`hex` 一族，93 份的
   `未定义的函数 hex/str/bin` 与之同源）；`#DATA_…` 的 `size(value)` 一面（`set_ram_value`）等它被调用时才会碰到。
5. **「同一 (函数, 实参) 只实例化一次」仍观测不到**：参考全内联。我们的策略按接口 §1 冻结版做成
   `fns_[(1, 名字, 行, 捕获签名|实例化串)]` 的缓存（同键复用同一个函数体），但**没有**参考行为可以对照。
