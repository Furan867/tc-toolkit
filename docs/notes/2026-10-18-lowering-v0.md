## 1. 分区

| 层 | 内容 | 落在哪 |
|---|---|---|
| 模块 | 三元组 `x86_64-pc-windows-gnu` + 固定 datalayout；**RelocMode = PIC** | `Program._make_context` / `emit_object` |
| 全局 | 顶层 `var`：`Ptr <addr>` / `raw_cast(<Arr[T]>, <addr>)` / 整数 / `Struct {}` / `false` → `internal global`，**初始化式是常量就直接写 LLVM initializer**（不生成运行期初始化代码） | `_make_globals` |
| 全局 | `const #NAME`（`Ptr`/整数）→ 编译期常量表，**不进 IR**；`const #NAME = [...]` 在函数体里 → `private constant` 数组 + 指针 | `_make_globals` / `array_literal` |
| 全局 | 字符串字面量 → `private constant [8+len+1 x i8]`（Nim 布局），值是 `getelementptr … , 0, 8` 的常量表达式 | `string_literal` |
| 全局 | 前缀（stdlib）里定义、本文件没声明的全局（`global_seed`）→ 按用到就建一个 `internal global i64 0` | `prefix_global` |
| 函数 | 程序根（`run_sim:` 顶层块）→ **`tc_main`（外部可见，shim 按名字找它）**，末尾隐式 `thread_exit()` | `emit_main` |
| 函数 | 其余 def **按需生成**：只有真被调用到的才发 IR（`_fn` 记忆 + 递归生成） | `ensure_def_fn` |
| 函数 | 嵌套 def → `<外层>$<名字>#L<行>`，捕获变量按**引用**当额外指针参数传 | `ensure_nested_fn` / `captures_of` |
| 函数 | 前缀函数 `get_time` / `sleep` / `memory_clear` / `memory_copy` → 我们自己发内部函数体 | `ensure_prefix_fn` + `_body_*` |
| extern | `thread_exit`（`rt_min.o` 提供）、`Sleep`、`GetSystemTimePreciseAsFileTime`（装配器造桩，宿主靠 sidecar 接） | `get_extern` |
| 局部 | 每个局部变量一个 `alloca`（插在 entry 块最前面，循环里声明也不吃栈），提升交给 `-O2` 的 mem2reg | `alloca` |

006 最终 12 个函数：`tc_main` / `reset_sim` / `set_error` / `get_command` / `get_setting` /
`set_setting` / `memory_clear` / `mode_refresh` / `mode_run` / `get_time` / `sleep` /
`mode_run$get_target_cycle#L365`。**`halt` 与 `handle_test_result` 不在里面** —— 它们的
调用点都在 `in_scope` 为假的块里，块被整块丢掉之后它们就是死的（按需生成自然不发）。

## 2. 类型映射表（Simplex → LLVM）

| Simplex | LLVM（值） | LLVM（内存） | 说明 |
|---|---|---|---|
| `Int` / `U64` / `S64` / `Time` / `Seed` / `Uint`/`Sint`（重载族） | `i64` | `i64` | `Time` 单位是纳秒（facts §006） |
| `U1…U64` / `S1…S64`（含非 2 的幂） | `i64` + 掩码 | `i8/i16/i32/i64`（`ceil(bits/8)`） | 不用 LLVM 原生 `iN`（U-L7 指示 2） |
| `Bool` | `i64`（0/1） | `i8` | 条件一律 `icmp ne x, 0` |
| `Ptr` | `i64`（游戏地址） | `i64` | 地址算术就是 `add i64`（U-L1） |
| `Str` / `Arr[T]` | **`ptr`** | `ptr` | 见 §3 的「为什么不放整数里」 |
| `Enum[X]` | `i64`（序号） | `i64`（未存过） | U-L5（enum 底层宽度）**未定**，暂按 64 |
| `Struct` | 聚合（`{}` 字面量 = `null`） | packed `{i8,…}`，字段按声明序 `ceil(bits/8)` 紧排 | U-L4 未定；006 里不可观测 |
| `None` | `void` | — | |
| `@Size` / `@Type` / 字符串模板 / 浮点 | **UNSUPPORTED** | — | |

掩码规则（`pattern_of` / `convert` / `mask_ll`）：SSA 里整数一律是该类型的**位模式**；
转换与运算结果两处掩码；**加宽**分两路 —— 编译期常量按源类型符号性 `sext`/`zext`，
运行期一律 `zext(trunc_W)`（U-L7 指示 3 + `ul7_narrow_var` 的复核）。

## 3. 语义档案 → IR 的逐条落法

| 档案条目 | 落地 | 代码 |
|---|---|---|
| **U-L1** 字节地址、无对齐、窄写只写该宽度 | 地址是 `i64`，`Ptr + k` 直接 `add`；每次 load/store 都 `align 1`，**不插对齐检查**；写宽度 `ceil(bits/8)` | `lvalue` / `load_addr`(525) / `store_addr`(539) |
| **U-L7** 位宽是真语义 | 位模式表示 + 两处掩码；`zext`/`sext` 分流见上 | `pattern_of`(478) / `convert`(490) |
| **U-L8** `>>` 是「扩到 64 位 → 逻辑右移 → 截回 W」 | `lshr(ext64(x), n & (W-1))` 再掩码 `W`；`ext64` 走 `pattern_of`（常量按符号性、运行期恒等）→ W<64 自动像算术右移、**W=64 自动是逻辑右移** | `binop`(1076) 的 `>>` 分支 / `fold_arith`(312) |
| **U-L8** 移位量按 W 取模 | 进 LLVM 移位前先 `and (W-1)`（LLVM 的越界移位量是 poison） | `binop` |
| **U-L8** `asr` 与 `>>` 不同 | 单独 lowering：按 W 位符号位 `ashr`，W<64 时移位量在 `W-1` **饱和**、W=64 走 `&63`，结果掩码 `W` | `builtin_asr`(1341) |
| **U-L8** 除零不 trap | `b==0 → 除数换成 1`（`select`，不是分支，避免 `#DE`），再 `select` 出「商 0 / 余数 = 被除数」；有符号再避 `INT_MIN/-1` | `div`(1110) |
| **`/`、`%`** opcode 看**被除数**声明类型的符号性 | `sdiv/srem` vs `udiv/urem` 只看左操作数；除数类型/常量性不参与 | `div` |
| **`/`、`%`** 两条不自洽照抄 | ① 两操作数都是常量 → 用精确值 + 被除数符号性折叠、**结果截断到 W**；② **运行期结果不截断到 W** | `fold_arith` / `binop` 的 `return V(ll, ty, None)`（不掩码） |
| **U-L14** `#if in_scope("name")` | 编译期谓词：**名字是顶层 def ⇒ 真，否则假**；假的块**整块丢掉、连名字都不解析**。裸 `if in_scope(...)` 同样处理（006 的 get_input/check_output 就是这种形态） | `in_scope_const`(731) / `s_PpIfStmt` / `s_IfStmt` |
| 数组/字符串布局 | `.len()` = `load i64, p-8` 再 `>>16`；字面量按 `(len<<16)|cap_log2` 造头，`cap_log2` 取 0 | `call_method`(1387) / `string_literal` |
| 006 的协议语义 | `#if` 三处全假；`mode_refresh` 从内存回读刚写的位；`Time` 是纳秒；`global_seed` 落我们自己的 .bss（宿主不比对那块） | `call_prefix`(1409) / `_body_get_time` |

**为什么 `Str`/`Arr` 的值必须是真 `ptr` 而不是 i64**：放进整数运算（`ptrtoint` + `add`）会让
后端生成 `movabs $imm64` + **ADDR64 绝对重定位**指向内部符号，而冻结的装配规则 §4 第 2 条拒收
（blob 会被拷到任意基址）。保持 `ptr` 就只会出 `lea rip+…`（REL32）。

## 4. 接口级决策：RelocMode = PIC（取代 §7 的 Static）

- **现象**：按 §7 的 `RelocMode=Static` 生成时，LLVM 对「往内部全局写常量」用绝对寻址
  `movq $imm32,[disp32]`，产物里出现 6 处 `IMAGE_REL_AMD64_ADDR32`（目标是我方内部全局
  `cycle` / `last_command_id`）；装配器照 §4 第 2 条直接拒：
  `装配失败（status=3）：.text+0x65 的重定位类型 0x2 不支持`。
- **改成 PIC 后**：重定位只剩 23 处 `IMAGE_REL_AMD64_REL32` + 3 处 `.pdata` 的 `ADDR32NB`
  （`.pdata` 按 §4 第 4 条整节丢弃）→ 装配通过、判据全绿。
- **裁定（负责人 2026-10-18，选 A）**：保持 PIC，不为 Static 找绕法。理由：产物被整体 memcpy
  到编译期未知的 JIT 基址，位置无关不是可选项；§4-2「拒绝指向内部符号的绝对重定位」是对的，
  矛盾在 §7 那个值（M1 spike 时空程序没有全局变量访问，从没被真实产物验证过）。
  旁证：clang 对该三元组默认 `-mrelocation-model pic`（`clang -###` 实测），
  `probe/006_equiv.c` 那条已验过的链路走的正是 PIC，所以从没踩到。
  §7 与 `facts.md` 由主程就地改；代码里保留 `RelocPIC`（`emit_object` 有注释指到两处）。

## 6. UNSUPPORTED 清单（`--list-unsupported`）

006：**0 条**（这是判据能过的前提）。

rv32im（`python simplexc/lower/ir_build.py --src simplexc/corpus/rv32im/rv32im.si --list-unsupported`）
→ **250 条，涉及 250 行**（占 M3.0 规模 5181 行的 ~4.8%，行号 220–10171），根因只有 **3 类**：

| 条数 | 根因 | 例子 |
|---|---|---|
| 38 | **三目 `cond ? a : b`**（`CondExpr`，前端已解析，lowering 未做） | `rv32im.si:977` = `load(<U1>, …) & 1 == 0 ? load(<U32>, …+484) : load(<U32>, …+476)`（`com_mux` 的每一路） |
| 2 | **空 `struct`**（`type Input Struct { }`）→ U-L4 布局未定 | `rv32im.si:220` / `:223` |
| 2 | 顶层 `var level_input = Input {}` 因为上一条建不出类型 | `rv32im.si:226` / `:227` |
| 208 | **连锁**：那 38 条三目所在的行是 `let x = cond ? …`，赋值失败 → 后续用 `x` 全报「未定义的名字」 | `rv32im.si:978` 起 |

**结论**：离 RV32IM 只差「三目」+「空 struct」两件事（第 3、4 类都是连锁）。除这两条外，
rv32im 可达闭包里的其余构造（`load`/`store`/`asr`/`min`/`max`/`Arr[i]`/`Str.len`/
`memory_copy`/`Ptr` 算术/移位/窄写/非 2 的幂宽度掩码）在本 lowering 下**都没有再报 unsupported**。
**没有量化的是「lowering 自洽但语义错」的那一档** —— 006 只有逐 tick 比对能证明，
rv32im 得等它能装配起来才有判据。

## 7. 未定 / 已知边界（别当已定）

1. **U-L5（enum 底层宽度）**：006 只把枚举当 i64 序号用（比较、传参），从没存进内存；
   rv32im 里 `#COUNTS[Int component_type]` 也没到。**没测过**。
2. **U-L4（struct 布局）**：按 `ceil(bits/8)` 紧排、packed、字段序；006 的 `level_input`/`level_output`
   只在我们自己的 .bss 里，宿主不比对 → 判据对布局**没有约束力**。
3. **U-L10（字符串逃逸/编码）**：只支持不含反斜杠的字面量（含 `\` 直接 UNSUPPORTED）；
   `cap_log2` 取 0（只有 `len = (p-8)>>16` 那半被用到）。
4. **闭包捕获语义**：U-未定（值捕获 vs 引用捕获）。这里实现为**按引用**（传外层 alloca 指针），
   对 006 的 `get_target_cycle` 两种语义不可分（它只读、且调用点前后没人改那几个变量）。
   捕获另一个嵌套 def 会报 UNSUPPORTED（006 的 `handle_test_result` 因此必须是死的，而它确实死了）。
5. **`store` 的非字节宽度**：`ceil(bits/8)`（U1 → 1 字节）。U-L7 只测过字节整数倍宽度；
   U1 这一档在 006 里也**不可观测**（邻居页字节两种写法最终相同）。
6. **参考实现的常量折叠边界**：我们把「`let` 绑编译期常量」当常量（`ul7_narrow_var` 的 fE 证据），
   于是 `fI`/`fI` 那条「运行期表达式被 LLVM 折成常量后按符号性 sext」的行为我们会**跟着 LLVM 走**
   —— `cycle - cycle - 8` 这类恒等式在 006 里不出现，没验证。
7. `asr` 在 W=16 的饱和点、`/` 在运行期×运行期的溢出（div_sign 未解 3/4）都没测，
   按 `dossier/ul8_shift_div.md` 指示 4 落「不 trap + 零除数按表」，不宣称全面保真。
8. **优化一刀没动**：只有 `default<O2>`；`-O2` 的 loop-idiom 会把我们的零填充/复制循环换成
   `memset`/`memcpy`（blob 没有 CRT，装配器报「外 symbol 解析失败」）→ 现在给每个函数加了
   `nobuiltin` 属性 + 那两处循环的访存标 `volatile`。这是**代价**：那两处循环拿不到向量化。

## 8. 下一步（按收益排）

1. **三目 `cond ? a : b`**（38 处，rv32im 只差它和空 struct）：`if/phi` 两臂（保证只有一臂求值，
   与短路语义一致），类型与掩码按 `unify` 走 —— 立刻能把 rv32im 的 208 条连锁清掉。
