## 已冻结的接口

`simplexc/frontend/ast.hh`（新，2026-10-18）：24 个节点**逐条对应** `frontend/expr.py` 的 dataclass，
包含字段顺序与可空性。设计取舍：

- 继承 + `NK` 枚举 + `as<T>()`（kind 由构造函数写死、不符返回 `nullptr`），不用 `std::variant` ——
  lowering 里按类别分派密集，variant 会把每处分派写成 visit + 重载集，离原型更远。
- `IfCase`/`SwitchCase` 有**独立**的 `NK`：与父语句共用会让 `as<IfStmt>()` 把 `IfCase` 认成 `IfStmt`。
- `LiteralExpr` 用 `has_value` + `value` 表示原型的 `int | None`（`=0` 与「没有值」必须分得开）。
- `TypeRef` 只存**源里的拼写**（名字解析/`@Size` 绑定属于 lowering）。

验证：`g++ -std=c++17` 编过；`as<IfStmt>(Block*)` 与 `as<IfCase>(IfStmt*)` 都返回 `nullptr`。

## 分工（一个写者一个目录）

| 路 | 目录 | 产出 | 判据 |
|---|---|---|---|
| **A** | `simplexc/frontend/` | `lexer` / `decls` / `parser` / `frontend` / `ast_dump` | **AST dump JSON 与 Python 原型 deep-equal**（≥4 个 def）+ `--all` 覆盖 + 错误路径一致 |
| **B** | `simplexc/lower/` | `llvm_ffi` / `lower`（Ty·V·fold·Lower·Program） | 手写 AST → COFF（只 `.text/.data/.bss`、`REL32`）→ `assemble::assemble()` → 合法 `Blob`（bit62、entry）+ 四条语义档案的 IR 证据 |
| 主程 | `cli/` / `tools/build.py` / 账本 | 接线、判据、文档 | 三条判据 |

**为什么 A 的判据是 deep-equal**：Python 原型已是冻结 oracle，`expr.py --json` 能导出整棵树
（`rv32im.si` 的 `mode_run` = 1.45 MB / 1117 条语句）。C++ 侧只要产出同构 JSON，
`json.load(a) == json.load(b)` 就是逐节点可比 —— 比「人读一遍」硬得多。

**B 为什么不等 A**：`ast.hh` 已冻结 → B 用手写 AST 就能把 lowering 与装配器闭环验完；
真源接入（L5）等 A 就绪。

## 写者冲突的规避

- `tools/build.py` 由 A 独占（加 `ast_dump` 目标）；B 被禁止改它，需要的 target 写在报告里由主程加。
