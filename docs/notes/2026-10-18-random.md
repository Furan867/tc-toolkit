## 1. `random` 的语义：自己复测

器材 `work/tmp/randomtask/probe_seq.py`（照 `work/tmp/stdlib/probe_stdlib.py` 的口径拼片段：
`work/tmp/ul7x/base.si` 头 44 行 + 探针声明，插进每 tick 的 cycle 内循环第一行）。

探针体与老探针不同的地方**只有一处**：老探针每次调用写 4 个槽（`random()`/`random(1)`/`random(2)`/`random(-1)`），
要靠「每 tick 跑几次」才能反推下标；新探针在**第一次**调用里连写 8 个槽 →
`ui_buffer + 20000 + 8k`（k=0..7）就是链上**连续**的 `state_1..state_8`，不依赖 tick 调度。

实测（`work/tmp/randomtask/seq.values.tsv`，参考产物 + 3 tick 宿主）：

| | 观测 |
|---|---|
| `state_1..state_8` | `4848f09881d3ddd1` `9c2b2a2bda08058c` `5cc95b686784a142` `7d4e885c71bb86a6` `c75b675c97dc9b97` `b0105816759385d1` `501dfb459869cd77` `959074466ddc899f` |
| 顺序式（前缀源码形状） | **8/8 逐位相同** |
| facts 的展平式 | 从 `state_2` 起就不同（`state_2` 给 `90ee09c74fa6e851`） |

自洽复核（与老探针的原始数据对得上，两条独立观测）：

- 老探针 4 列的数据（同一次跑 `python work/tmp/stdlib/probe_stdlib.py store` 重放）里
  `20000/23000` 两列 = 本次的 `state_1, state_5, state_9, state_13` 与 `state_4, state_8, …`；
- `22000` 列 `random(2)` = `0 1 1 0` = `state_3/7/11/15` 的奇偶，本次观测的 `state_3` 偶、`state_7` 奇 → 对上；
- `21000` 列 `random(1)` 全 0。

**我们的产物也逐位对上**（实现完之后的端到端复核）：
`build/simplexc_cli.exe --src work/tmp/randomtask/seq.si --out …/seq.ours.bin`（entry `0x6F0`）→ 宿主 1 tick
→ `ui_buffer+20000` 起 8 个槽与上表 **8/8 相同**。

`random(m) = U64(state) % U64(m)`、`m == 0` 返回被除数、`m < 0` 按 U64 重解释 —— 这三条**沿用 facts 里的口径**
（本次没重测，它有老探针的逐位证据）。

## 2. 实现要点（`simplexc/lower/lower.cc` / `lower.hh`）

| 点 | 做法 | 为什么 |
|---|---|---|
| 种子 | 复用 `global_seed` 这一份前缀全局（`seed_global()`：先查 `globals_`，没有再 `prefix_global`） | 98 份语料**每份**都写 `global_seed = Seed (get_command(ctl_test) + 1)`（`reset_sim` 里，且 `reset_sim` 可达）—— 另建一份就等于不播种 |
| 初值 | `PrefixGlobal { ty, init }`，`global_seed` 的 `init = 1`（原来是 `LLVMConstNull`） | 前缀写的是 `var global_seed = Seed 1`；实测第一版输出 = `f(1)` |
| 递推 | `x ^= x<<12` → `x ^= x>>25` → `x ^= x>>27` → `* 0x2545F4914F6CDD1`，**返回新 state** | §1 |
| `random(m)` | `div("%", state, m, U64)` —— 现成的运行期 `%`（零除数换成 1 再 `select` 回来） | `n == 0` 返回被除数、不 trap；`n < 0` 走 U64 位重解释 |
| 没做的 | `random(@Type)` / `sample(Arr[@Any])` / `randomize_seed()` | 语料 0 份用（`randomize_seed` 要 `rdtsc` + `$` 参数） |
| 空数组字面量 | `Arr[U8] []`：元素类型只在外面那层转换上（`ArrayLitExpr` 不带类型），所以从 `e_CastExpr` / `cv` 的转换处进 `empty_array()`：8 字节零头 + 空载荷的私有常量全局（= `array(<T>, 0)` 的表示） | 157 的 `var outputs = Arr[U8] []`；`.len()` = 头 >> 16 = 0 |

⚠️ 参考侧那个空数组指针是它 arena 的分配结果，我们给的是私有常量 —— **未实测**（157 里 `outputs`
每个分支都先赋值再用，读不到空值）。标「未验」。

## 5. 遗留风险

1. `docs/facts.md` 的 `random` 递推式仍是**展平式**（错的）—— 本轮没权限改账本，需负责人就地改写。
   别拿它当实现依据。
2. `random(m)` 的边缘口径（`m == 0`、`m < 0`）本轮**没重测**，只沿用老探针的观测。
3. 空数组字面量的**指针值**未与参考对照（只有「长度 0」这一条被消费者用）。
4. `random(1000)` 这类**运行期实参**在语料里没出现（32 份全是整型字面量），`div` 那条路只在
   单测/自测里走过；真出现时要按「同一调用点两次求值」复核。
5. `global_seed` 的初值从 0 改成 1 只影响读种子之前不写种子的程序 —— 语料全是先写后读；
   但这是**行为改动**，见判据（全等份数没掉）。
