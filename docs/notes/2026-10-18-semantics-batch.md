## U-L2 数组下标越界 —— 无边界检查、无夹取，只有硬件 AV

| 探针 | 片段要点 | 参考侧原始输出 | 结论 |
| --- | --- | --- | --- |
| `oob_c_read` | `var a = array(<U8>,4)`，读 `a[4]`、`a[8]` | `+20000: b'11,44'`、`+21000: b'0'`、`+22000: b'0'`（`load(<U8>,p+4)`）、`+23000: b'5'`、`+24000: b'5'`（`load(<U8>,p+8)`） | 常量越界读 = 载荷 + i，**静默**且与裸 `load` 同值；编译期不报错 |
| `oob_c_write` | `a[4] = 99` | 写前 `load(p+4)=0`；写后 `{a[4]}=99`、`load(p+4)=99`；`a[0],a[3]` 不变 | 越界写静默落到载荷外第 4 字节，**不 trap**、不污染已有元素 |
| `oob_r_read` | `i=4` / `i=8` 运行期下标 | `+20000: b'0'` = `load(p+4)`；`+22000: b'5'` = `load(p+8)` | 运行期下标与常量下标**无区别**（都不检查） |
| `oob_r_neg` | `i = -1` | `+20000: b'262149'`（`load(<U64>,p-8)` = 长度头 0x40005）、`{a[-1]}=0` = `load(<U8>,p-1)` | 负下标不夹取，读的是长度头最高字节 |
| `oob_r_far` | `i = 1<<20`（写） | 宿主 VEH：`异常 code=0xC0000005 addr=产物+0x221E params=[1, 70378745229320]` | 远越界 → **原生访问违例**；`70378745229320 = 0x4002541bf008 = 载荷 0x4002540bf008 + 1 MB` |

地址式 = `载荷 + i * 步长`，四处证据一致；没有任何 trap/夹取分支。所谓「越界」的可见后果只有：
要么读到/写到相邻内存（小偏移），要么硬件 AV 打死宿主（远偏移）——参考不给错误消息。

## U-L5 enum 底层宽度 —— 只按成员数定，只有 1/2 字节两档

`size(v)`（= 该值类型的位数）与「`array(<E>,2)` 载荷首 u64」（= 前两个元素的字节）双口径：

| 成员数 | `size(v)` | 载荷首 u64（步长） | 取值 | 判据 |
| --- | --- | --- | --- | --- |
| 2 | 8 | `256` = 0x100 → 步长 1 | `Int (E e1)` = 1 | `enum_2` |
| 256 | 8 | `65280` = 0xFF00 → 步长 1 | `Int (E e255)` = 255 | `enum_256` |
| 257 | 16 | `16777216` = 0x1000000 → 步长 2 | `Int (E e256)` = 256 | `enum_257` |

`enum_65536`、`enum_65537` **参考自己断言失败**（同一句）：

```text
fatal.nim(53)            sysFatal
Error: unhandled exception: front_end.nim(282, 13) `enum_names.len < 1 shl 16`  [AssertionDefect]
```

→ 规则：**≤256 员 → 1 字节；257…65535 员 → 2 字节**（成员序号从 0 起，`Int`/`U64` 转换零扩展）；
4/8 字节档**不可达**（参考在 65536 就断言死）。`Char`（256 员，1 字节）与 U-L10 的字符串步长自洽。

「显式指定宽度」的语法：**未验**（只试过 `Enum[...]` 一种形状；语料里也没有第二种）。

## U-L10 字符串字面量编码

转义表（`{load(<U64>,p)}` = 前 8 字节拼成的 u64，逐字节读）：

| 转义 | 实际字节 | 探针 |
| --- | --- | --- |
| `\0` | 0x00 | `esc_nul`（`a\x00b\x1bcPQR`） |
| `\a` `\f` `\v` `\e` | 0x07 / 0x0c / 0x0b / 0x1b | `esc_table`（`A\x07B\\bC\x0cD\x0bE\x08F\x1bG`） |
| `\n` `\r` | 0x0a / 0x0d | `esc_nt`（`a\nb\x08c\rdP`，`len=7`） |
| `\t` | **0x08**（不是 0x09） | 同上，两次独立片段都出 0x08 |
| `\b` | 原样两字符 `\` `b`（不认这个转义，保留反斜杠） | `esc_table`，`len=14` |
| `\"` | 原样两字符 `\` `"`，且**不结束字面量** | `esc_q`：`"x\"y"` → `b'x\\"y'`、`len=4` |
| `\\` | `Could not parse this.` —— 不可用 | `esc_bs`：`"x\\y"` 解析失败 |
| `\x42` | 字面 4 字符 `\x42`（无十六进制转义） | `str_hex`：`"A\x42é"` → `b'A\\x42\xc3\xa9'`、`len=7` |

布局（`str_esc`/`esc_nt`/`str_hex`）：

- 头 8 字节 = `len << 16`，**低 16 位为 0**（`esc_nt`：`load(<U64>,p-8)` = `458752` = 0x70000，`len=7`）。
  对比 U-L4 记的 `array()` 载荷头低 16 位 = 5/7（`0x40005` / `0x20005`）—— 字面量是**静态数据**、不是堆分配。
- 载荷 = 源文件原始字节，UTF-8 直通（`é` → `c3 a9`，计入 `len`）。
- **无 NUL 终止**：`load(<U8>, p+len)` = `0x50`（'P'）、`p+len+1` = `0x51`；`esc_nul` 里载荷后紧跟 `PQR`
  → 后面是别的常量数据，不能当终止符用。

`Str` 与 `Arr[Char]`：**互不兼容的具名类型**，两个方向都被拒（`str_arr_1` / `str_arr_2`）：

```text
No function matched sem_take_arr(Str).       … Got Str
No function matched sem_take_str(Arr[anon_enum]). … Got Arr[anon_enum]
```

旁证（**未定论**，没动账本）：`var a = "abc"` / `var b = "abc"` 的指针不同（`0x212291c2137` /
`0x212291c2142`，差 11），但 `{a == b}` = `true`、`{a == "abd"}` = `false` —— 可能是编译期折叠，
不能据此说 `==` 比内容（`str_id`）。

## U-L12 `min` / `max` 类型规则 —— 结果类型 = **第一个实参**的类型

| 调用 | 值 | `size(expr)` | 判据 |
| --- | --- | --- | --- |
| `min(U8 200,U8 100)` / `max(U8 200,U8 100)` | 100 / 200 | 8 / 8 | `mm_uniform` |
| `min(S8 -5, S8 5)` | -5 | 8 | 同上（有符号按有符号比） |
| `max(U64 18446744073709551615, U64 7)` | 全 1 | — | 同上 |
| `min(3,5)` / `max(3,5)` / `min(-3,5)` | 3 / 5 / -3 | 64 | `mm_lit`（字面量 → Int） |
| `min(U8 200, U16 300)` | 200 | **8** | `mm_mixed_width`（不提升） |
| `min(U16 300, U8 200)` | 200 | **16** | `mm_rev_width`（顺序反了就 16） |
| `min(U8 200, U64 300)` | 200 | 8 | `mm_int_mix`（不升到 64） |
| `min(S8 -5, U8 5)` | -5 | 8 | `mm_mixed_sign` |
| `min(U8 200, S8 -5)` | **200** | 8 | `mm_rev_sign`（第二实参 → U8 251，min=200） |
| `min(3, U8 200)` | **-56** | 64 | `mm_lit_typed` |
| `min(3, U16 60000)` / `max(3, U16 60000)` | **-5536** / 3 | 64 | `mm_lit_typed2` |

规则：**结果类型 = 第一个实参的类型**（无算术提升、无「宽者赢」、无符号统一）；
第二实参转成该类型时**按它自己的宽度做符号扩展**（`U8 200` → `-56`，`U16 60000` → `-5536`）。
没有出现过编译错误 —— 混合宽度/混合符号都能编译，只是被静默重解释。

## U-L6 `$` 参数写回

- 形状：声明 `def f($x: Int)`，调用点 `f($g)`（与 `$global_seed.next()` 同形）。
- **存在性已验**：调用返回后调用者可见 ——
  - `dollar_two`：`sem_set($sem_k, 7)` → `{sem_k}` = 7；
  - `dollar_min`：调用前 `{sem_g}` = 1 → 调用后 = 7，被调方内赋值后自读 = 7。
- **时机（立刻透写 vs 返回时拷回）未验**：两条路都撞上参考自身的问题，记下绕过：
  - 源码里一旦出现 `$xxx` 实参，**在那枚变量之外的地方读它**就报 `Variable xxx does not exist.`
    （第三方 def 体内 `dollar_wb`、被调方自己体内 `dollar_now` 都是这一句）；
    同一份代码不写 `$` 时正常编译（`gvar_read` PASS）→ 与 `$` 无关的全局读取没问题。
  - 两个 `$` 形参绑同一变量（`dollar_alias`）→ 只给 `COMPILER ERROR`、**无消息**（参考自己崩的形状）。

## 未验 / 风险

- U-L2：无——常量与运行期两条路都测了，结论一致。**未测**的是越界**写**到「别的东西头上之后的行为」
  （比如踩坏数组头再 `.len()`）——本批没做。
- U-L5：4/8 字节档不可达（参考断言死）；「显式指定宽度」语法**未验**。
- U-L6：写回**时机未验**（见上，参考侧有 `$` 相关缺陷）。
- U-L10：`Str == Str` 的旁证未定论（可能编译期折叠）；`\t`=0x08 与 `\b` 不认是参考的表本身如此
  （同片段 `\n`/`\r` 正确 → 不是我的读法问题）。
- 所有结论都只覆盖「参考产物在差分宿主里跑 2 tick」这一口径；游戏内未复核。
