# U-L4：复合字面量的字段初始化（实测规则 + 实现）

日期 2026-10-18 · 改 `simplexc/lower/{lower.cc,lower.hh}` · 现场 `work/tmp/ul4/`

**结论先行**：字段初始化能编了 —— 95 份 cli_fail 里那一类（48 份）**不再停在复合字面量**，
但**一份也没变成「能装配」**：它们各自撞上后面的另一个缺口（§5 逐类）。`check.py` 5 PASS、
rv32im 10 tick 差异 0、改前 equal 的 176/177/180 仍是 equal。

## 1. 实测到的语义（每条带怎么验的）

器材 = `work/tmp/ul4/e2.py`：把探针插进 `work/tmp/ul7x/base.si`（一段参考编得动、宿主跑得起来的
完整单元），参考编译 → 差分宿主跑 2 tick → 读 `ui_buffer` 页里 `set_text` 写下的字节。
**为什么必须插进完整单元**：参考 `compile()` 对不完整单元返回固定 8581 B 桩（本文件 `e1_layout.si`
实测 8581 B、产物里搜不到任何字段标记），最小片段只给「接受/拒绝」一个信号。

| 规则 | 实测 | 怎么验的 |
| --- | --- | --- |
| 未列字段的默认值 = **零** | `Lay { b: U32 0xA1B2C3D4 }` 的 `a`/`c`/`d` 渲染出来都是 `0` | `e2.py ref` 的 `g4_part.a(未列)=0`、`c=0`、`d=0` |
| **字段名顺序无关**（按名字匹配，不是按位置） | `Lay { c: .., b: .., a: .., d: .. }` 四个字段值全对（17 / 2712847316 / 51 / 72623859790382856） | 同上 `g4_w.*` 四行 |
| 求值顺序 = **源码书写顺序** | `Lay { c: U8 (u4_second()), a: U8 (u4_first()) }` 里两个函数都写共享标志 `u4_seq`，读到 **1**（后者写的）= 先 `second()` 后 `first()` | `u4_seq(求值顺序) len=1 b'1'`；反过来写才是 2 |
| 字段值是**运行期表达式**（`load`/调用）也支持 | `var s = Lay { a: U8 (U8 load(<U64>, commands)) … }` 编译通过、`s.b = U32 (c+1)` 渲染出 `1` | `e2.py ref` 的 `s.b(运行期)=1`、`s.d=2` |
| **顶层 `var x = T {…}`**（不在函数体里）参考也接受 | `var g4x = Lay { a: U8 0x11, b: U32 0xA1B2C3D4 }` 参考 `成功`（blank 单元：`type`+`var` 插进 005 后产物不再变） | `work/tmp/ul4/try.py` 的 `i_foo_fields`（`OK blob=12621`） |
| **偏移 / padding / 嵌套 struct / 按值传递的布局** —— **没测出来**（见 §2） | | |

## 2. 没测出来的那一条：字段偏移

三次尝试都撞在同一面墙：**参考产物在这种形状上是不可观测的**。

1. 最早直接把探针插进 005.si（`work/tmp/ul4/e1_layout.si`）：产物与基线**逐字节相同**。不是编译没生效
   （同位置插一句 `level_input.input = U1 1` 产物就变，尾部塞垃圾会编译失败），而是**只写不读的
   internal 全局被参考的优化器整块消掉**（把字段值 `set_text` 出去，产物立刻变大：32481 B）。
2. 想过从「全局初始化数据」里读布局：全局在 `ui_buffer` 那类外部内存区、由**发出来的代码**写，
   而不在变化页里；且在变化页里搜 4/8 字节标记 = 0 命中。
3. 反汇编（`objdump -D -b binary -m i386:x86-64`）也不给：字段标量被常量折叠（我写
   `g4_w.d = U64 0xAABBCCDDEEFF0011` 后，产物里只剩十进制渲染循环那几条比较），带运行期值的
   `var s = Lay {…}` 又被 SROA 拆成各自独立的栈槽 —— 栈槽间距是**分配器的**结果，不是布局。

⇒ 现有的 `packed`（`ceil(bits/8)` 紧排、声明序、`field_offsets_` 前缀和）**这一轮没有被验证**，
它在这轮之前就长这样（`docs/notes/2026-10-18-lowering-v0.md` 标的就是「U-L4 未定」），本任务**没有改它**。
下次要测，最小可判据是：让一个**非空 struct 按值穿过调用边界**（语料的
`check_output(cycle, input: Input, output: Output)` 就是），或让 `Arr[T]` 的步长把 `sizeof(T)` 露出来
（`&a[1] - &a[0]`），这两条都不会被 SROA/常量折叠吃掉。

## 3. 实现（`lower.cc`，两处）

- `composite_literal()`：字段值按**源码顺序**求值（先求值、再拼聚合，两趟分开就是为保住副作用顺序）
  → 未列字段取该字段元素的零值 → 全常量时用 `LLVMConstStructInContext`（顶层 `var` 那条路没有
  builder，只能靠聚合常量），有运行期值时用 `LLVMConstNull` 底座 + `LLVMBuildInsertValue`。
  字段名不在 struct 里 → `Unsupported("struct X 没有字段 Y")`。
- `const_for_storage()` 的 struct 分支：`v.ll` 存在时用它，别再把「带了字段初始化的顶层 var」
  静默变成全零。
- `field_storage_value()`（新）：字段/元素的**存储形态**值，与 `store_addr` 同一套窄化口径。

**踩到的坑（写进代码注释了）**：**不在函数体里时不能走 `e()`**。`var x = T { a: U8 (f()) }` 这种
顶层初始化式在第一版里让 CLI 直接 AV（`rc=0xC0000005`，复现 `work/tmp/ul4/iso4.py` 的 `t_ord_call`）——
`e()` 是按「有 builder」写的。改成常量环境走 `const_value()`（它遇运行期表达式返回 `nullopt`）→
现在是干净的 `UNSUPPORTED: 顶层 var … 的初始化式不是编译期常量`。

## 5. 48 份现在停在哪（**只分类，没动**）

| 份数 | 下一道缺口 | 例 |

| 21 | 嵌套 def 调用另一个嵌套 def（`halt`） | 001、005 |
| 11 | 未定义的名字 `#CORRECT_OUTPUT` | 008 |

前两类是「闭包捕获传递」与「程序根变量 + 前缀常量」，正是 `docs/notes/2026-10-18-in-scope-fix.md`
§3 那两条需要主程定的架构口径 —— **复合字面量只是排在它们前面**，不是它们的成因。

## 6. 途中发现的参考侧行为（不是我们的事，记下来）

1. **只写不读的 internal 全局会被参考整块消掉**（§2 第 1 条）—— 拿参考产物做实验时，「产物没变」
   未必等于「源码没生效」。
2. **词法把 `U4S` 切成 `U4` + `S`**：`type U4S Struct {…}` 之后写 `var x = U4S {…}`，
   参考报 `Expected U4 here.`（`try.py` 的 `c/d/e/f/l` 全失败）；换个不以 `U1/U2/…/U32` 开头
   的名字（`Foo`）就正常。**类型名以 `U<数字>` 开头只在初始化式位置炸**，声明位置没事。
3. **顶层 var 的运行期初始化参考支持**（`var g4_ord = Lay { a: U8 (u4_first()) }` 参考编得过，
   我们的 CLI 报「初始化式不是编译期常量」）—— 与 098 里「程序根 `var` 是全局还是栈槽」是同一个
   未定项，别在 U-L4 里顺手做。
