# 窄位宽的真条件（176/177/180 反例夹逼）

2026-10-18。片段/脚本/原始表：`work/tmp/widthcond/`（`base.tsv` = 改前 · `all.tsv` = 全铺 → 破 ·
`A/B/C/B1/B2.tsv` = 算符分组 · `line.tsv` = 行区间 · `*.si`/`*.ref.*`/`*.ours.*` = 探针）。

## 0. 结论

1. **「宽侧是常量 → 取窄侧」这条规则本身没错**，`+ - * & | ^ << >> / %` 与 `== != < >` 全铺在
   176/177/180 上破，**成因不是规则错，是 `<<`/`>>` 的移位量掩码用错了宽度**：
   旧代码用 `andi (ty->bits - 1)`，只有位宽是 8 的倍数时才对（8/16/32/64 都凑巧对，所以旧注释里
   「铺给 `%`/`<<`/`/` 会破」的现象只在**非 8 倍数位宽**的语料里出现）。
2. **真条件（参考实测）**：

   | 项 | 规则 | 判据 |
   |---|---|---|
   | 结果类型/掩码 | **窄侧的声明位宽 W**（U12 → 掩 12 位） | `x12 + 1` = 0 · `x12 * 0x10` = 0xFF0 · `x3 + 1` = 0 |
   | 移位量掩码 | `8*ceil(W/8) - 1`（**存储宽度**取模，不是 W−1） | `x14 << 2` = **0x3FD4** · `x3 >> 3` = 0 · `x7 >> 8` = 0x7F |

   `+` 之外全部与我们的 `arith_ty` 判据同形（宽侧必须是常量、窄侧必须是运行期声明窄值）。
3. **原 20 点表里没有反例**（那批全是 U8/S8，8 = 1 字节 → 两种宽度同解，分辨不出来）。
   反例只在**非 8 倍数位宽**（U1/U2/U3/U5/U7/U12/U14/U30…，解码器输出满屏都是）上出现。
4. 176 的 4 个最小致因窗口（`bisect_line.py` 二分，脚本按 `SIMPLEXC_NARROW_LINE` 闸）：

   ```
   904  let value_id568 = (U14 (load(<U12>, #SIMULATION_STATE+540)) << 2)
   1357 let value_id668 = (U1 (load(<U3>, #SIMULATION_STATE+662) >> 3))
   1506 let value_id714 = (U12 load(<U5>,…) | ((U12 load(<U7>,…)) << 5))
   6509 var vid568 = U14 (U14 ((U12 vid540)) << 2)          // 同 904 的解码变体
   ```
   四个都是「窄左操作数 + 常量移位量」：U14 的 `<< 2` 旧代码算成 `2 & 13 = 0`、U3 的 `>> 3`
   算成 `3 & 2 = 2`、U7 的 `<< 5` 算成 `5 & 6 = 4`。

## 1. 分组实验（`coverage --ids 176,177,180`，改前 3 份全等）

| 组 | 算符 | 结果 |
|---|---|---|
| A | `+ - * & \| ^` | 3 份**全等** |
| B | `<< >> / %` | 3 份**全 diff**（4/2/4 tick） |
| C | `== != < > <= >=` | 3 份**全等** |
| B1 | `<< >>` | 3 份全等（单看时不显形） |
| B2 | `/ %` | 3 份全等 |

分组只用来定位嫌疑面；B1+B2 合起来才破，说明不是某个算符单独错，而是「类型一旦变窄，
**移位量掩码跟着变窄**」这条路本身有错 —— 由此找到第 0 节的机制。

## 2. 参考实测（`probe.py`，全部 ≤ 4 tick 落盘）

`work/tmp/widthcond/probe.py mask_bits|shamt|shamt2|arith_mask|cmp_mask|u1`，原始输出在各组
`*.ref.compile.log` / `*.ref.pages`。要点：

- **结果掩码按声明位宽**：`x12 << 6` = 0xFC0（12 位；16 位假设会给 0xFFC0）· `x5 << 4` = 0x10（5 位）·
  `x7 << 2` = 0x7C（7 位）· `x14 << 2` = 0x3FD4（14 位）· `x30 << 2` = 0x3FFFFFFC（30 位）。
- **移位量按存储宽度取模**：`x12 << 12` = 0（声明位宽假设给 0xF00）· `x14 >> 14` = 0（声明位宽给 3）·
  `x3 >> 3` = 0（声明位宽给 1）· `x5 >> 5` = 0（声明位宽给 1）· `x7 >> 8` = 0x7F（mod 8）·
  `x9 << 4` = 0x1F0（mod 16 保留 4）· `x16 >> 17` = 0x7FFF（mod 16）。
- **比较也窄化常量**：`x12 == 0x10FFF` = 1 · `x3 == 0x107` = 1 · `x12 >= 0x1001` = 1。
- **未解释**：`U1`/`U2` 侧的移位量掩码像 `mask_of(W)`（`x1 << 4` = 1 · `x1 >> 1` = 0 · `x1 >> 4` = 1 ·
  `x2 << 4` = 3），与 W ≥ 3 的「存储宽度 − 1」相冲（W=1 时那是 0、W=2 时是 3）。
  本形状没查到语料依赖（语料里 `<<`/`>>` 的左操作数都是 U8 及以上），**按存储宽度实现、把 U1/U2 记为未解**。
