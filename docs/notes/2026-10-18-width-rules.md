# 算术 / 位运算的窄位宽规则（参考实测）：**宽侧是常量 → 整条表达式取窄侧**

2026-10-18。只读产品代码；片段与驱动在 `work/tmp/width/`。原始表：`work/tmp/width/run.log`。

## 0. 结论

1. 「宽侧是常量就取窄侧」是**一整条规则**，不是 `+` 的个例：`- * << >> / % | ^` 与 `== != < >`
   **全部**按**窄侧的位宽 W** 算（常量按 `mod 2^W` 截断、结果按 `(1<<W)-1` 掩码、移位量按 **W** 取模），
   一宽一窄共 20 个观测点里 20 个都指向窄侧，**参考侧一个反例都没有**。
2. 触发条件与我们的 `arith_ty()` 判据一致：**窄的一侧必须是运行期值、宽的一侧必须是常量**。
   窄侧是常量（`x64 - U8 5`）、或两侧同宽（`x64 - 300`）时**不做窄化**（两侧各验一行，都一致）。
3. `const #K300` 这种**具名常量**在参考侧同样算「常量」（`x8 - #K300` = 0x94 = 窄算），
   而我们的 `pat_const()` 认不出它（我们算成 64 位的 `0xFFFFFFFFFFFFFF94`）—— 这是**独立于「只给了 `+`」的另一处缺口**。
4. `&` **构造上不可分辨**：窄操作数 < 2^W 时 `(a & b) & (2^W-1) == a & b` 恒成立，所以 `&` 不在差异清单里，
   但也不等于「参考对 `&` 走了别的路」—— 只能说这个形状观测不到。
5. 参考对**有符号窄类型**走符号扩展：`S8 (-64) < 0` = **true**（在 8 位上做有符号比较），
   我们 zext 成 192 后按 `slt i64 192, 0` 得 **false**。⇒ 参考是「把两边都化成窄类型再在该类型内比较」，
   不是 U-L7 那条「运行期窄值一律 zext」的转换路径。
6. 参考侧**没有一个形状崩**，不需要绕。

## 3. 我们现在的行为（IR，`--ir-out` 的 `mode_refresh`）

```llvm
; `+`：窄化（arith_ty 的既有行为）—— 常量 300 先截成 44、结果掩 8 位
%op20 = add i64 %m19, 44          ; %m19 = zext(load i8 %x8) & 255
%m21  = and i64 %op20, 255
; `- * | ^`：完全不窄化
%op25 = sub i64 %m24, 300         ; %op33 = mul i64 %m32, 100
%op45 = or  i64 %m44, 256         ; %op49 = xor i64 %m48, 256
; `&`：and i64 %m40, 448（值恰好相同）
; `<< >>`：移位量按 **64** 取模（`and 63` 被 O2 折掉）、结果不掩 8 位
%shl22 = shl  i64 %m21, 32        ; %shr = lshr i64 %m25, 9
; `/ %`：opcode 取**统一后类型**的符号性 —— `x8 / 300` 出的是 `sdiv i64`（参考按 U8 走 udiv）
%q = sdiv i64 %m18, 300
; 比较：一律按 i64 比较，且运行期窄值 zext
%cmp = icmp eq i64 %m18, 448      ; %cmp37 = icmp slt i64 %m36, 0
```

要点：

- 我们的窄化只挂在 `binop` 的 `arith_ty()`（`lower.cc:1527`），且 `op == "+"` 写死；
- `pat_const()` 认不出 `const #K300`；
- 比较走的是另一条路（不经过 `arith_ty`），符号扩展也只在 `pattern_of` / 显式转换里有；
- `<<`/`>>` 的移位量模数是 `ty->bits - 1`（这里的 `ty` = 64）。

## 4. 差异清单（按「改动会不会动到别的形状」分组）

1. **窄化面**（唯一成因）：`- * | ^ << >> / %` + `== != < >` —— 把 `arith_ty` 的 `op == "+"` 放开即覆盖，
   但**别一次全放**：`lower.cc` 的注释记着「套到 `%`/`<<`/`/` 上会让 176/177/180/rv32im 从全等掉成 diff」，
   那是**当时**的实测，本轮没复核；放开前必须逐算符跑 `coverage.py` 全量。
2. **具名常量的常量性**：`pat_const(#K…)` 认不出（一个独立症状，修不修都独立）。
3. **有符号窄值的符号扩展**：参考在窄类型内做有符号比较/运算，我们一律 zext（U-L7 的转换规则没有覆盖
   「窄类型内部比较」这一形状）。
4. **`/`、`%` 的 opcode 符号性**：窄化一旦落地，`ty` 会变成窄类型，符号性跟着变 —— 与 facts 那条
   「opcode 由**被除数**声明类型决定」是否等价，本轮**未验**（本形状里 udiv/sdiv 值相同，分辨不出）。

## 5. 未验 / 风险

- `>`、`>=`、`<=`、`!=` 只验了 `>`/`!=` 各一行（其余同族，未逐条测）。
- `S8/S16/S32` 只验了 `S8` 两行（`*`、`<`）；「窄侧 16/32 位」整片没测。
- 两侧**都**是变量的情形（一宽一窄、宽的是运行期值）没测 —— 本轮只夹了「宽侧常量」这一侧。
- `and/or/xor` 之外的位运算（`~`、`rol`/`ror`）没测。
- 参考侧没崩过，没有需要绕过的形状。
