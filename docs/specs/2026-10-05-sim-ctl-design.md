# 设计：仿真控制工具 simctl

- 日期：2026-10-05（2026-10-06 重写 `recompile` 一节：进程内调用路线废弃，改用 UI 事件注入）
- 分支：`feat/sim-ctl`
- 状态：`run`/`stop` 已改为**按键注入**（F6 / F4，2026-10-06），待游戏内实测；`recompile` 机制已实测打通，待写实现计划

## 目标

让外部脚本能脚本化这一循环：**改 opt.ini → 重编译 → 运行 → 停止 → 再改**。
本工具只负责其中「重编译 / 运行 / 停止」三个动作，供其他脚本调用。

## 接口

核心模块 `tools/simctl.py`，暴露三个函数：

```python
simctl.run()         # 启动电路运行
simctl.stop()        # 停止电路运行
simctl.recompile()   # 触发一次重编译
```

- 三者都返回结构化结果（成功/失败 + 原因），失败给原因
- 内部缓存进程句柄；PID 或模块基址变化时自动重查（游戏重启、Steam 更新后地址位移）
- 另附同名 CLI 薄壳，供手工敲或其他语言调用（`import` 比每次起解释器快，这是留函数接口的原因）
- CLI 与模块有一处行为差异：**CLI 退出前会把焦点还给调用前的窗口**，模块不还
  （模块生命周期长，中途用户可能自己切焦点）。判据见「抢前台」末节

## 行为契约

### `run`

**注入 F6**（游戏的「运行 / 暂停」键），复用 `recompile` 那套流程：抢游戏窗口到
前台 → 校验前台确实是游戏 → `SendInput` 按下并抬起 F6 → 返回「键已发出」。

⚠️ **F6 是切换键**，语义与旧的写内存版不同：

| 版本 | 行为 |
| --- | --- |
| 旧写内存（实现保留在 `simctl._publish`） | 把 `commands[0]` 置成 `0`(run) + `settings[1]=INT64_MAX` —— **幂等**，已在跑时再调还是在跑 |
| 现在的 F6 注入 | **切换** —— 已在跑时调用会**暂停** |

所以调用者若要「确保在运行」，得自己记住当前状态（或先读 `set[14]` sim_running
再决定发不发）。这是换用 UI 路径的代价。

判据：注入后 `set[0]` (sim_cycle) 开始递增、`set[14]` (sim_running) 变 1。
（旧写内存版实测：1 秒后电路跑起来，读到 10.75 MHz。）

### `stop`

**注入 F4**（游戏的「停止」，即复位）。流程与 `run` 完全相同。

判据：`set[14]` (sim_running) 变 0、`set[0]` (sim_cycle) 归到哨兵值。

> 旧写内存版用的是 `commands[0] = 3` (quit_simulation)：实测日志（40.1s）确认
> 「停止」按钮与「编辑电路时自动停止」共用它；而 `2` (mode_reset) 是暂停，
> 语义不同。该实现保留在 `simctl._publish`，本工具已不用。

> 说明：`3` 是「停止」按钮与「编辑电路时自动停止」共用的命令（实测日志 40.1s）。
> `2` (mode_reset) 是「暂停」，语义不同，本工具不用。

### `recompile`

**机制：UI 事件注入。** 不去调用游戏内部函数，而是注入按键，让游戏自己走
「电路变化 → 重建场景 → 编译」那条路。

固定序列，无分支：

```text
1. 抢游戏窗口到前台（AttachThreadInput + 先模拟一次 Alt 解锁前台限制）
2. 校验前台确实是游戏 —— 不是则中止，绝不发键
3. SendInput 发**一个**键：net 记账 > 0（欠着撤销）就发 Ctrl+Shift+Z（重做），
   否则发 Ctrl+Z（撤销）—— 即按净消耗交替
4. 记账：发 undo 则 net +1，发 redo 则 net −1
5. 返回「按键已发出」，不判断编译是否成功
```

**为什么是单键交替，而不是成对发**：

- 撤销与重做**各触发一次重建 + 编译**，效果等价
- 成对发送会平白多记一次编译（近 1 s）；交替发送把**净消耗维持为 0**，既不偏离原状，
  也不浪费一次编译
- 连续两次只发 Ctrl+Z，第二次无操作可撤销就不会触发 —— 交替正是为了绕开这一点，
  所以不需要记忆「上次发的是哪个」，只需记「净欠多少步」
- 净欠不为 0 时，`restore_stack()` 在退出（atexit / SIGTERM）时补发等量反向键，把撤销栈
  还给用户；`simctl` CLI 是一次性进程，用 `forget_restore()` 主动放弃补偿

实测：一次 Ctrl+Z 或一次 Ctrl+Shift+Z，`next_sim_version` 都 **+3**（游戏内部固定发 3 次编译请求）。

### 不做的事（设计原则）

- **不做自动检测**：不监听 opt.ini 的 mtime、不做任何"发现变化就自动重编译"。重编译一律由外部**主动调用**触达。
- **不判断编译是否成功**：编译成功必然经过 `compile.dll`；调试靠转发层日志或主频工具，工具本身不另加判据，徒增复杂度。
- **不改 opt.ini**，不做计时，recompile 后不自动 `run`。

## 前提与调用者责任

| 前提 | 说明 |
| --- | --- |
| 游戏在运行 | 否则返回失败 |
| 电路**有可撤销的编辑历史** | 否则 Ctrl+Z 无事可做 → 不会触发。调用者需保证电路刚被编辑过（例如加一根线） |
| **处于电路编辑模式** | 不是运行模拟时 |
| **重编译 / 运行 / 停止期间前台会被抢走** | 用户会短暂失去焦点，这是本方案的代价 |

## 抢前台

`SetForegroundWindow` 从后台进程调用**会被前台锁拒绝**（表现只是任务栏图标闪一下）。
实测：agent 启动的 python、前台是 VS Code 时，直接调用返回 `False`。

有效手段（已实测两次成功）：

1. 先 `SendInput` 发一次 **Alt 键**（`VK_MENU` 按下+抬起）—— 系统会放宽前台限制
2. `AttachThreadInput(本线程, 前台线程, TRUE)` 把自己的输入队列接到前台线程
3. `BringWindowToTop` + `SetForegroundWindow`
4. 之后 `AttachThreadInput(..., FALSE)` 解除

**安全铁律**：发键前必须校验 `GetForegroundWindow() == 游戏窗口`。
`SendInput` 把键发给**当前前台窗口**，抢前台失败时若仍发键，**会把 Ctrl+Z 打到别人的程序上**
（实测中真的误发给了 VS Code）。校验不通过 → 中止并报错，绝不发键。

**已在前台时不做任何抢台动作**：`force_foreground` 首行即
`GetForegroundWindow() == hwnd` → 直接返回，不按 Alt、不 AttachThreadInput、
不等那 0.3 秒。每次调用仍会做的是只读部分（查 PID、枚举窗口找主窗口并查错误
对话框、两次前台比较）与按键本身（2×60 ms）。

**CLI 的焦点归还**（2026-10-06）：`main()` 在动作前记下前台窗口，动作后满足
「焦点确实变了 + 此刻焦点仍在游戏窗口 + 记下的窗口仍然存在」三条时才用同一套
`force_foreground` 还回去。第二个条件是为了不打断用户 —— 若这期间用户自己切走了
焦点，再抢回来等于抢用户。模块调用不做归还，失败静默（best-effort）。

## 并发约定

`simctl` 的每个动作同一时刻只允许一个在执行，内部用一把文件锁串行化，跨进程有效。
并发调用排队等待，而不是交错执行 —— 否则两次 `recompile` 的按键会交错，状态不可预期。

## 实测记录（2026-10-06）

| 方式 | 结果 |
| --- | --- |
| `PostMessage`（投递 `WM_KEYDOWN`，不需要前台） | ❌ **不通**。窗口是 GLFW 的，投递的按键（含修正 scan code 后）游戏不响应，`next_sim_version` 不变 |
| `SendInput` + 抢前台 | ✅ **可用**。两次连测（前台起点均为 VS Code）：`119 → 122`（undo）、`122 → 125`（redo） |

判据用 `next_sim_version`（`.data 0x14049c300`）：每次编译请求 +1，**纯读内存，不需要转发层**。

## 风险

- 写内存与抢前台都可能扰动用户的桌面状态；用户已接受
- 所有地址依赖进程实例，游戏重启即失效（工具自动重查）
- Steam 更新会让函数地址位移，需重新确认
- 若游戏更新改了撤销/重做（Ctrl+Z / Ctrl+Shift+Z）或运行-暂停/停止（F6 / F4）的快捷键，本机制失效
- `run` 走 F6 后**失去幂等性**（切换键）：按旧语义用的脚本，可能在想启动时把仿真暂停
