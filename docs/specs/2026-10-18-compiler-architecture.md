## 1. 分层与层间契约（框架级）

```
源码 ──[frontend]──▶ AST ──[sema]──▶ HIR ──[codegen]──▶ LLVM IR ──[assemble]──▶ blob
```

| 层 | 输入 | 输出 | 只做这些 | **禁止** |
|---|---|---|---|---|
| `frontend` | 源码文本 | 无类型 AST + 诊断 | 词法、语法、预处理、构造清单 | 类型推导、名字解析、常量求值 |
| `sema` | AST | HIR | 名字/重载解析、类型推导、常量求值、泛型实例化、可见性 | 发 IR、碰 LLVM 任何类型/句柄以外的状态 |
| `codegen` | HIR | LLVM 模块 | 语义→IR 映射、内建表、extern 声明、entry 包装 | 回头查源码、重做类型推导、改 HIR |
| `assemble` | COFF + 元数据 | blob + entry + sidecar | 重定位、桩/槽、8 字节头、生命周期 | 解析源码、关心语言语义 |

**依赖方向**：只能自右向左 include（`assemble` 不 include `sema`，`codegen` 不 include `frontend`）。
违反即编译期错误（头文件不放跨层类型）。

**HIR 不变量**（sema 的输出必须满足；codegen 可以据这些直接发指令）：
1. 每个表达式节点带**宽度 + 符号性**（不是"类型名"）；不存在"未定类型"。
2. 每个名字引用已解析到具体声明；不存在自由名。
3. 每个泛型/闭包调用已实例化为具体实例；不存在未定类型参数。
4. 每个节点带 `span`（行、列）。
5. 每个 def 实例有唯一键（见 §5）。
6. 隐式转换已显式化（`trunc/zext/sext` 由 sema 决定，codegen 不再判断）。

**不自研 MIR**：LLVM IR 即 MIR，优化全部交给 LLVM。本文档不定义任何"我们的中间表示"。

**与 `interfaces` §1 的关系（2026-10-18 决定）**：`interfaces` §1 冻结的
`Type`/`TypeKind`/`TypedProgram`/`parse_and_typecheck` **从未实现**（全仓不存在；`TyRef` 实际定义在
`lower/lower.hh`，sema 逻辑住在 `lower.cc`）。本文档正式取代它：
分层形态是「`frontend` 出**无类型 AST**，`sema` 出 HIR」，不是「`frontend` 直接出类型化 AST」。
HIR 的**具体类型表示**仍需重新冻结（在哪一层定义类型、用什么数据结构），
但那属于 `sema` 的契约，不属于 `frontend`。

## 2. 语义权威（框架级）

1. **唯一权威 = 原版编译器的实测行为**。文档、代码注释、旧实现都不能推翻实测。
2. 结论的登记位置是 `docs/facts/semantics.md`（每条带「验证：」与「最后验证：」）+ `simplexc/dossier/`。
3. 允许修改语义结论的条件：**有可复跑的实测证据**。推断（🔍）只能进 notes，不能进 facts，不能作为设计依据。
4. 冲突时的优先级：**实测 > 本文档 > 代码注释**。发现冲突时改文档或改代码，不许两边都留着。
5. 不存在"某个实现是权威"这一层：M3 期的 Python 原型已删除（git 历史可查），其行为**不再约束任何东西**。

## 3. 错误模型（框架级）

**三个正交的轴**，缺一个就没法归因：

| 轴 | 取值 | 用途 |
|---|---|---|
| **责任（blame）** | `user`（源码写错）/ `unimplemented`（我们没做）/ `internal`（我们的 bug） | 回退率的分子分母 |
| **阶段（stage）** | `read` `lex` `parse` `sema` `codegen` `llvm` `assemble` | 定位与熔断 |
| **位置（span）** | 行、列；缺失时显式记为"无位置" | 用户可操作的报错 |

规则：
1. **span 从词法一路带到 C 边界**，不允许在层间降级成"只有一段文本"。缺位置必须显式标注，不能悄悄变 0 或 -1。
2. **未识别的构造必须报错**（`unimplemented`），**禁止当成合法代码继续**。静默降级会让错误出现在很远的地方。
3. 错误分类必须能映射到 `hook.log` 的 `impl` 词表与回退率统计；不能只有"失败"一个比特。
4. 游戏侧只拿得到"类别"，拿不到 span（C 边界限制）—— 所以 span 的消费者是离线 CLI 与 sidecar，不是游戏。

## 4. 状态与所有权（框架级）

1. **分层调用，层次拥有状态**：每层在入口处创建自己的 context，通过参数向下传；返回即销毁。
2. **禁止"可变成员 + 手工保存/恢复"**：不得出现 `save_state()/restore_state()` 这类成对操作。
   需要嵌套上下文时，创建子 context 并显式传下去。
3. **跨层只传值/不可变引用**；一层的内部可变状态不得作为另一层的成员。
4. **不变式用 `assert` 表达**，而不是注释。断言是给人看的"这条不能破"，破了要在开发期就炸。
5. 所有权规则（谁分配、谁释放、生命周期）必须写在类型或注记上，不能靠约定俗成。

## 5. 实例化策略（策略级）

**问题**：泛型、闭包捕获、编译期条件都会产生"同一份源码、多个具体版本"。

契约：
1. **键**（判定"同一个实例"）= `(def 标识, 类型实参规范化, 环境类型)`。
   **不含调用点**——按调用点区分会在嵌套时爆炸。
2. **实例化在 `sema` 完成**，`codegen` 只看到已实例化的 HIR。
3. 用**待办队列**驱动（遇到新键入队，处理到队空），不得递归隐式展开。
4. 每个实例**记录来源**（原 def、实参、捕获集合），并进入 sidecar（§8 用得上）。
5. **无界情形**（如递归泛型）→ 显式报错、`blame=unimplemented`，计入回退率。
   **不允许**用"实例数上限"当语法：上限可以存在，但必须报可归因的错误。
6. 闭包捕获在 `sema` 做闭包转换（捕获变成显式的环境参数），保证键与环境类型一致。

## 6. 内存与优化假设（策略级）

分成两件不同的事，不要混：

**(a) 语言语义（已实测，不可协商）**：见 `docs/facts/semantics.md` U-L1。
访问宽度 = `ceil(N/8)`（`N ≤ 32`）或 8 字节（`N > 32`）；`N ≤ 32` 不越写邻居，`N > 32` 会清后 2–3 字节；
`load` 与 `store` 对称；`N < 8` 为整字节访问。**codegen 必须精确复刻，包括"会踩邻居"这种古怪行为。**

**(b) 我们向 LLVM 声明的优化假设**：是一个**可开关的集合**，默认取最保守，逐条用实验换取。
- 对齐：语言无对齐要求 → 默认 `align 1`。声明更强对齐必须先证明所有地址都满足。
- 别名：内存访问是"字节地址 + 宽度"，**不因数据类型不同而互不别名** → 不按类型做 TBAA。
- **区域模型**：优化只能基于"内存区域声明"（谁写、是否可能与其它区域重叠），
  而不是基于"我们观察到的布局"。布局是**输入**，不是常量：将来若有人改动游戏的内存分配，
  只需改区域声明，优化决策自动跟着变。
- 每条假设都要有：默认值、开启条件、验证方法、失效时的影响。没有验证方法的假设不得开启。

## 7. 判据体系（策略级）

1. **每个模块有接缝**：能单独喂输入、单独判输出（不依赖整条链）。没有接缝的模块视为设计缺陷。
2. **最小用例**：`sema` 的每条类型/常量规则、`codegen` 的每条关键路径，各有一个最小 `.si` 或最小 HIR。
   大语料只能证明"没崩"，不能证明"这条规则对"。
3. **覆盖率口径必须"卡点前置"**：先解掉前置阻塞（否则全部语料停在同一个错误上，矩阵没有信息量），
   再统计"构造 × 文件"。统计前要说明"本次统计的语料实际跑到了哪一层"。
4. **单测 vs 差分的边界**：
   - 不变式 / 单元行为 → `assert` 或最小用例（快、定位准）
   - 语义等价 → 逐 tick 差分（慢、唯一可信）
5. **三道门**（依赖门、延迟门、回退率）由判据入口统一跑，任一不过即判失败。
6. 判据产物必须落进仓库（不能只留在临时目录），否则"跑过"无法被复核。

## 8. 调试信息与性能归因（策略级）

**目标**：给定一个机器码偏移（采样得到的 RIP），能回答"这是哪段源码、属于哪个执行单元"。

1. **形态**：产物旁的 sidecar 文件（**不进 blob**，不影响产物字节、不影响性能）。
2. **必须提供**：`机器码偏移区间 → 源码行区间 → 标识`。
   "标识"由实现与下游协商（执行单元的划分方式不在本文档规定）。
3. **获取方式**：`codegen` 为每条语句设 debug location → 编译带 `-g` → 行号表随目标文件产出
   → `assemble` 把行号表重映射到 blob 偏移。这是目前已知唯一可靠来源；若有更廉价的方式可替换，
   但"偏移→行"这一层信息不得缺失。
4. **可扩展**：sidecar 允许新增字段（实例来源、opt level、pass pipeline 摘要），消费者忽略未知字段。
5. **不要求**：DWARF 的变量/栈帧/类型信息；标准调试器可读性。

## 9. 回退语义（策略级）

1. **粒度 = 整单回退**：任何失败都不产出"混合产物"。混合正确性风险不值得。
2. 失败必须按 §3 三轴记录，否则回退率不可解释。
3. 关闭回退的条件：回退率降到目标值以下 **且** 语义档案覆盖全部已支持构造。
   目标值写进里程碑，不写在本文档。
4. "回退成功"不等于"我们正确"：回退率低只说明覆盖面够，正确性仍以逐 tick 差分为准。

## 10. 文档治理（框架级）

1. **本文档只写"必须成立的东西"**。凡属"我们打算怎么做"的，进实现或 notes，不进这里。
2. 每条条款标注级别：
   - **框架级**：写错就要重写实现（分层、权威、错误轴、状态、治理）
   - **策略级**：定原则与判据，细节自由（实例化、内存假设、判据、调试信息、回退）
3. **里程碑开工前逐项自检**：本文档每一条是否已被实现满足？缺项即不开工。
4. 修改本文档的框架级条款 = 改契约：需登记版本并通知所有在跑的写者。
5. 会过期的东西（数字、路径、外部工具版本）不写进条款；需要时写成"在哪查"。
