### 下一步（已决定）

**只剩 M5（全语料覆盖）**，它没做完之前不开新的优化战场：

1. **98 份语料**：现在可装配 **29/98**。两类缺口的诊断已完成 ——
   ① 模板字面量 `{…}` 插值（49 份，语义已实测、**是 66 份的共同前置**）·
   ② `return` 后多余的 `)`（17 份，已窄修 `d5c9e82`，它们转而撞上 ①）。
   修 ① 是装配率 29.6% → ~85% 的那一步。
2. **campaign 的 92 份**：**已查明：它们不是编译单元** —— 游戏在关卡测试时会把 `test.si` 拼进一个完整程序
   （含 `run_sim` 主循环 + 游戏内存地址 + Input/Output 类型）再交给 `compile.dll`：证据是那 98 份捕获里
   **98/98 含 `def get_input`/`def check_output`**、13 份含 `#CORRECT_OUTPUT` 且值与 `test.si` 对得上。
   → 拿 `test.si` 直接喂 CLI 是**输入口径错误**，「92/92 装不出来」不是缺口。
   **待定：还要不要去抱齐这 92 个关卡的完整程序**（那是采集问题，不是编译器问题），由负责人定。
3. **stdlib 前缀（路线 A）** —— 把 27711 B 前缀也交给我们的前端；这是终态，决定能不能关掉回退。

### 待定 / 未解

- 剩余语义：`U-L2`（数组下标/越界）、`U-L3`（`Str` 是否 NUL 终止、`+` 拼接的分配语义 —— 它是 ① 的前置）、
  `U-L4`（struct 布局）、`U-L5`（enum 底层宽度）、`U-L10`（字符串字面量编码）、`U-L12`（min/max 类型规则）
  —— **写一条验一条**。
- **`-O0` 伏笔**：M4 的 25.835 MHz 是 Python 原型 `-O0` 代码生成的成绩（`ir_build.py` 把 `CodeGenOptLevel` 写成 0）。
  C++ 走正确的 2、产物小 2.2 倍 → **游戏内更快是待测的**，别拿 25.835 当 C++ 产物的基线。
- 034 / 090 的**参考产物**在宿主里间歇崩溃（AV，重试时好时坏）→ 这两份的差分判定不稳定，不能据它判我们的产物。
- 游戏内真环境未验（真 `Sleep`/时钟、游戏设的 `target_cycle`）。
- `entry`（`Result[2]`）用途仍只知「相对机器码起点的偏移」。
- `campaign/` 的 92 份没编译过；参考产物的热环没定位到（要 RIP 采样）。
