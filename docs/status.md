### 下一步（已决定）

1. **9 份「产物在宿主里 AV」**（001/047/048/049/050/051/053/054/124）—— 这是**正确性问题**，优先查：
   故障指令是 `__simplexc_copy` 向量化后的 32 字节 store，写目标等于入口第二参数；最像「模板里有 Str 段 →
   动态 `alloca` 拿到垃圾长度把 `rsp` 带飞」（**未验**）。
2. **闭包捕获 ~30 份**（`counter` 12 · `test` 4 · `instructions` 3 · `input` 2 · `memory` 2 · 另 7 个各 1）——
   要改函数 ABI，**先定方案再动手**。
3. **前缀函数 `str` / `bin` / `hex`**（已定位到 `stdlib_prefix.si:1110-1234`；渲染语义与 `render_part` 同一套，可直接当内建实现）。
   另：3 份报 `kernel32!memcpy` 未解析（IR 之后的 pass 认了某个拷贝循环）。
4. **路线 A 的三个大机制**（泛型实例化 · inline asm 小汇编器 · 算子单元重载表）—— **能做就做，现在不投**（前端那三类已落地，是净收益）。

### 待定 / 未解

- 未验的语义：`U-L4` 的偏移/padding（三次尝试都不可观测）· `$` 的写回时机 · `U-L5` 的显式宽度语法与 4/8 字节档 · `Str == Str` 是否编译期折叠。
- **`-O0` 伏笔**：M4 的 25.835 MHz 是 Python 原型 `-O0` 代码生成的成绩；产品（C++ 产物）是 **40.375** —— 别混用。
- 宿主那 23 份的 **extern 条数**相对改前变了（页/段/`sim_cycle` 仍逐 tick 全等）—— 只差 extern 时别当成内存语义差异。
- 已知但未修的差异：顶层非声明语句被整体丢掉 · 参考对 `return a) + 1` 是静默吃掉后面的一切（我们只吃一个 `)`）·

- `entry`（`Result[2]`）用途仍只知「相对机器码起点的偏移」；参考产物的热环没定位到（要 RIP 采样）。
