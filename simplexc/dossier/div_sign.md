# div_sign：`/` 与 `%` 的符号性（参考实现实测，已定）

**结论**：`/`、`%` 的 **opcode 由「被除数的声明类型」的符号性决定**（有符号 → `sdiv`/`srem`，无符号 → `udiv`/`urem`），
**除数不参与判断**（它的类型、是不是编译期常量都不影响）；「常量 / 运行期」本身**不是**判据。
但**参考前端把两个窄类型字面量折叠出来的常量当「W 位模式」零扩展成 64 位**送去做那个**有符号**除法 ——
所以 `(S32 0 - S32 7) / (运行期 2)` 给出 **2147483644**，而 `(S32 (-7)) / (运行期 2)` 给出 **-3**：
两者 opcode 都是 `sdiv`，差别在**操作数的 64 位值**（4294967289 vs -7）。

## 结论 1：opcode 跟被除数的声明类型走，除数完全无关

- **除数类型无关**：`f5` `+280`（S32 运行期 −7 **/ U32 运行期 2**）= `fd ff … ff` = −3（有符号）；
  `f5` `+296`（**U32 运行期** 0xFFFFFFF9 **/ S32 运行期 2**）= `fc ff ff ff ff ff ff 7f` = 9223372036854775804 = **udiv**。
  同一份片段里两个方向都测了；`f4` `+376/+384/+392/+400`（除数换成 U32 运行期构造）逐个重复同样结论。
- **除数常量性无关**：`f1` `+280`（除数 = 常量 2 → −3）与 `+312`（除数 = 运行期 2 → −3）在被除数同为运行期时一致；
  `f5` `+384`（除数 = 折叠常量 `S32 0 - S32 2`，值 −2）→ `00 …` = 0 = `sdiv(-7, 4294967294)`，与「除数无关」一致。
- **opcode 是 sdiv/srem 还是 udiv/urem，靠「同一被除数 + 符号反转的除数」证死**（`f8`，除数 = 运行期 −1 / −2）：

| 被除数 | 除数 | `/` 字节 | `/` 值 | 只有 sdiv 才能得到 | 只有 udiv 才能得到 |
|---|---|---|---|---|---|
| 运行期 S32 −7 | 运行期 S32 −1 | `07 00 00 00 00 00 00 00` | 7 | 7 ✓ | 0 |
| **折叠常量** `S32 0 - S32 7` | 运行期 S32 −1 | `07 00 00 00 ff ff ff ff` | **−4294967289** | `sdiv(4294967289, −1)` ✓ | 0 |
| **折叠常量** `S32 0 - S32 7` | 运行期 S32 −2 | `04 00 00 80 ff ff ff ff` | −2147483644 | `sdiv(4294967289, −2)` ✓ | 0 |
| 折叠常量 `U32 0 - U32 7` | 运行期 S32 −1 | `00 …` | 0 | 7 | `udiv(4294967289, −1)` ✓ |

  → 折叠常量被除数用的是 **S32 类型的 sdiv**，但操作数是 **4294967289**（0xFFFFFFF9 零扩展），不是 −7。
  组合 3 的 2147483644 = `sdiv(4294967289, 2)`，**不是** `udiv`。**「无符号」这个说法在组合 3 上是错的**，
  它只是「有符号除法 + 常量被零扩展」的巧合结果。

验证：`bash work/tmp/div/run.sh f8`（`out_len=0x359F`/13727 `entry=0x212F` `bin_md5=670a6f2f5cec` `page md5=112e970f7873` 两遍 SAME）
      `bash work/tmp/div/run.sh f5`（`out_len=0x3B68`/15208 `bin_md5=2e1f38e34e05` `page md5=cc9a410ae4f7`）

## 结论 2：类型角色 —— 改被除数类型会翻，改除数类型不会；负字面量/收窄/load 都是正常有符号

`S32` 与 `U32` 取同一 bit pattern `0xFFFFFFF9`、除数都是运行期 `2`（`f2`/`f5`）：

| 被除数构造 | 声明类型 | 64 位物证 | `/` 结果 | `%` |
|---|---|---|---|---|
| `S32 (t0 - 7)` | S32 | `f9 ff…ff` = −7 | −3 | −1 |
| `U32 (tu - 7)` | U32 | `f9 ff…ff` | 9223372036854775804 | 1 |
| `U32 a_s`（S32→U32 转换） | U32 | `f9 ff…ff` | 9223372036854775804 | 1 |
| `S32 n_u`（U32→S32 转换） | S32 | — | −3 | −1 |
| `U32 cycle - U32 10`（两侧都 U32） | U32 | `f9 ff…ff` | 9223372036854775804 | 1 |
| `S32 cycle - S32 10`（两侧都 S32） | S32 | `f9 ff…ff` | −3 | −1 |
| 字面量 `S32 (-7)` | S32 | `f9 ff…ff` | −3 | −1 |
| Int 常量收窄 `S32 (0 - 7)` | S32 | `f9 ff…ff` | −3 | −1 |
| Int 运行期收窄 `S32 (cycle - 10)` | S32 | `f9 ff ff ff 00…`（⚠ 这是 store 转换后的形态；除法用的操作数是 −7，见「未解 1」） | −3 | −1 |
| **两个 S32 字面量折叠** `S32 0 - S32 7` | S32 | `f9 ff ff ff 00…` | **2147483644** | 1 |
| store→load 回读（`load(<S32>, …)`） | S32 | `f9 ff ff ff 00…` | −3 | −1 |

两处要点：
1. **除数声明成 S32 还是 U32 都不改结果**（`f5` `+280` vs `+296`、`f2` `+392`/`+400`、`f4` `+376…+400`）。
2. **被除数类型翻结果**（上表前两行 / `f2` `+264` vs `+280`），但**只有「两个窄类型字面量的二元运算」这一种常量**例外 ——
   它被零扩展（`U64` 物证是 `f9 ff ff ff 00…`），运行期表现为「4294967289 参与运算」。
   负字面量（`S32 (-7)`）、Int 表达式收窄（`S32 (0 - 7)`）、store→load 回读都不是这种特例，**都是有符号 −7**。

      `bash work/tmp/div/run.sh f4`（`out_len=0x3DC8`/15816 `bin_md5=445dd0563735` `page md5=18d100919c16`）
      `bash work/tmp/div/run.sh f6`（`out_len=0x3B27`/15143 `bin_md5=0cb9c81b17e4` `page md5=92c692cc227f`）

## 结论 3：宽度 —— S8 / S16 / S32 符号性一致（只有折叠结果的截断宽度不同）

`f3`（每档都有「常量/常量」与「运行期/运行期」两组，被除数/除数都 store 出来）：

| 宽度 | 常量 ÷ 常量 | 运行期 ÷ 运行期 | 折叠常量被除数 ÷ **运行期**除数（`f6`） |
|---|---|---|---|
| S8 | `fd 00…` = 253（8 位 −3）/ `ff 00…` = 255（8 位 −1） | `fd ff…ff` = −3 / `ff ff…ff` = −1 | `7c` = **124**（= 0xF9/2） |
| S16 | `fd ff 00…` = 65533（16 位 −3）/ `ff ff 00…` = 65535（−1） | −3 / −1 | `fc 7f` = **32764**（= 0xFFF9/2） |
| S32 | `fd ff ff ff 00…` = 4294967293（32 位 −3）/ `ff ff ff ff 00…` = 4294967295（−1） | −3 / −1 | `fc ff ff 7f 00…` = **2147483644** |

- 运行期那一列三档**完全一致**（都是 −3 / −1，符号扩展到 64 位）；
- 常量/常量那一列三档也一致 —— 值在**本宽度**里截断成 W 位模式（U-L7 的「结果按 `(1<<N)-1` 掩码」在本路径上同样成立）；
- **零扩展那个坑在三档宽度上都出现**（`f6` 的 `S8 0 - S8 7` → 124、`S16 0 - S16 7` → 32764）；
  `S32 (S16 0 - S16 7)`、`S32 (S32 0 - S32 7)` 这种**再套一层 S32 转换也洗不掉**（仍是 32764 / 2147483644）。

验证：`bash work/tmp/div/run.sh f3`（`out_len=0x39B1`/14769 `entry=0x212F` `bin_md5=abbf98de5798` `page md5=03acbc468565`）
      `f6` 见结论 2 的命令；原始字节 `work/tmp/div/bytes.txt` 的 `f3`/`f6` 段

## 未解（别当已定）

1. **零扩展这件事的内部机制**（为什么折叠窄常量在 codegen 里用 `zext` 而不是 `sext`）没有继续往下定：
   观测上等价于「该常量在运行期的 64 位值 = 它的 W 位模式」。同一节点在**编译期折叠路径**里却按类型解释
   （`(S32 0 - S32 7) / (S32 2)` = −3，见 `f7` `+264`；`(U32 0 - U32 7) / (U32 2)` = 2147483644，`f7` `+272`）——
   两条路径不一致，这是参考实现自己的不一致，别当成语言语义。
2. **U32 运行期值的 udiv 用的是 64 位表示**：`f5` `+296` = 9223372036854775804，而不是按 32 位截断后再 udiv 的 2147483644。
   也就是「无符号除法的操作数是寄存器里的 64 位内容，没先截到 W」。本任务没继续定它（要定得先定 U32 运行期值的寄存器表示）。
3. **运行期结果没截断到 W**：`f8` `+280` = −4294967289 超出 32 位范围（该片段的被除数是折叠常量）。
   运行期×运行期的溢出行为**没测**（要测得构造商超出 W 的一对运行期值）。
4. 只做了 S8/S16/S32：`S64`/`U64`/`Int`/`U8`/`U16` 与其他非 2 的幂宽度没测。
5. 除数是折叠常量、被除数运行期的组合只测了一例（`f5` `+384`），没铺满。

## 对 lowering 的直接指示

1. **`/` 发 `sdiv` 还是 `udiv`，判据 = 被除数（左操作数）的声明类型符号性**：
   `S8/S16/S32/S64/Int` → `sdiv`（`%` → `srem`）；`U8/U16/U32/U64` → `udiv`（`%` → `urem`）。
   **不要**看除数：除数的类型、常量性都不参与（结论 1 的四组实测）。也不要用「两边都 signed 才 signed」的规则。
2. **两个操作数都是编译期常量**时，参考在编译期折叠，用**精确值 + 被除数的类型符号性**、结果**截断到 W 位**：
   `(S32 0-S32 7)/(S32 2)` = −3、`(S32 0-S32 7)/(S32 0-S32 2)` = 3、`(U32 0-U32 7)/(U32 2)` = 2147483644、`S8` 折出 `0xFD`。
   → 这条路上按类型发 `sdiv`/`udiv` 并让 LLVM 自己折叠，结果与参考一致。
3. **折叠窄常量做运行时被除数**时，要复现参考的零扩展（否则 `(S32 0 - S32 7) / 2` 我们给 −3、参考给 2147483644）：
   发 `sdiv(zext64_W(c), <除数>)`，`c` = 该常量的 W 位模式（`S32 0 - S32 7` → `zext i32 0xFFFFFFF9 to i64` → 4294967289）。
   触发条件是**源里的形状**：两个窄类型字面量的 `+`/`-` 运算（`S32 0 - S32 7`、`S32 0 + S32 (-7)`、`S8 0 - S8 7`）。
   负字面量、`Int` 表达式收窄、运行期值、`load` 出来的值**都不触发**（它们都是正常有符号值）。
   ⚠ 这条跟 LLVM 的自然折叠相反（LLVM 会把 `(i32 0 - i32 7) / 2` 折成 `i32 -3`），必须在**前端/常量造型**那一步就按参考分好类。
4. 运行期**结果不截断到 W**（`f8` `+280` = −4294967289 就是 64 位结果），而**折叠路径截断到 W** —— 两边都要照做。
5. 别用 LLVM 原生 `iN`（N∉{8,16,32,64}）承载（U-L7 已定）；这里只是补上「`/`、`%` 的符号性不由位宽决定，三档一致」。
