# U-L8：移位 / 除零 / `asr`（参考实现实测，已定）

**结论**：`>>` **不是**「signed→算术、unsigned→逻辑」这么简单 —— 它等价于
**「把操作数按声明符号性拓宽到 64 位 → 逻辑右移 → 截回声明宽度 W」**，所以
**W=64 的有符号 `>>` 是逻辑右移**（`S64 -8 >> 1 = 0x7FFFFFFFFFFFFFFC`）；
移位量一律先 `& (W-1)`（硬件式取模，不是「越界给 0」）；`asr` 与 `>>` **只在小移位量、W<64 时一致**，
`asr` 永远按 W 位符号位算术右移、且移位量在 W 处**饱和**（W=64 例外，走 `&63`）；
除零**不 trap**：商 0、余数 = 被除数（除数非 0 时 `/`、`%` 的符号性另有问题，见「未解 1」）。

| # | 问题 | 实测答案 |
|---|---|---|
| 1 | `S32 -8 >> 1` / `U32 0x80000000 >> 1` | `0xFFFFFFFC`（**算术**，低 32 位）/ `0x40000000`（逻辑）；`S64 -8 >> 1` = `0x7FFF…FFFC`（**逻辑**） |
| 2 | 移位量 ≥ 位宽 | 按 `W` 取模：`U32 1<<32=1`、`U32 1<<33=2`、`U32 1>>32=1`、`U8 1<<8=1` |
| 3 | `7 / 0`、`7 % 0` | `0` / `7`；**不崩、不 trap**、3 tick 全绿（有符号同款：`-7%0 = -7`）。⚠️ 非零除数时 `/`、`%` 的符号性不稳定（见「未解 1」） |
| 4 | `asr(x,n)` vs `x >> n` | W=32、n<32 时**一样**；n≥W 时不一样（`asr` 饱和→`-1`，`>>` 取模）；**W=64 时完全不一样**（`asr` 算术 `-4`，`>>` 逻辑 `+0x7FFF…FC`） |
| 5 | `U8 1 << 8` | `1`（既不是 `0` 也不是 `0x100`）：移位量 `8 & 7 = 0` |

## Q1 `>>` 对负数：低 32 位是算术，W=64 是逻辑

片段 `q1.si`（tick 3）：

```text
let s32neg = S32 -8
store(+264, U64 (s32neg >> 1))
store(+272, U64 (U32 (s32neg >> 1)))
let u32hi = U32 0x80000000
store(+280, U64 (u32hi >> 1))
store(+288, U64 (U32 (u32hi >> 1)))
```

```text
+264  fc ff ff ff 00 00 00 00     0x00000000FFFFFFFC  → 低 32 位 = 0xFFFFFFFC = **-4**（不是 0x7FFFFFFC）
+272  fc ff ff ff 00 00 00 00     同上
+280  00 00 00 40 00 00 00 00     0x40000000 = **逻辑**
+288  00 00 00 40 00 00 00 00     同上
```

**W=64 反了**（片段 `q1b.si`，`let s64neg = S64 -8`）：

```text
+264  fc ff ff ff 00 00 00 00     U64 sr            （sr = S32 -8 >> 1）
+272  fc ff ff ff 00 00 00 00     U64 (S64 sr)      ← 加宽到 64 位是**零扩展**
+280  f8 ff ff ff ff ff ff ff     U64 (S64 s32neg)  ← 对照：**常量** S32 -8 →S64 是符号扩展
                                                  （运行期窄变量则是零扩展，见「未解 2」）
+296  fc ff ff ff ff ff ff 7f     U64 (s64neg >> 1) = 0x7FFFFFFFFFFFFFFC = **逻辑右移**
```

运行期值同款（`q1c.si`：`rn = S32 (cycle-11)`、`rn64 = S64 (cycle-11)`，tick 3 都是 -8；
排除「只在常量折叠时如此」）：

```text
+264  f8 ff ff ff 00 00 00 00     U64 rn              = 0x00000000FFFFFFF8
+272  fc ff ff ff 00 00 00 00     U64 (rn >> 1)       = **-4**
+280  f8 ff ff ff ff ff ff ff     U64 rn64            = -8（确实是 -8）
+288  fc ff ff ff ff ff ff 7f     U64 (rn64 >> 1)     = 0x7FFF…FFFC（逻辑）
+296  ff ff ff ff ff ff ff 1f     U64 (rn64 >> 3)     = 0x1FFF…FFFF（逻辑）
```

→ 机制（唯一能同时解释 W=8/32/64 的模型）：`x >> n` = `lshr64(按 x 的声明符号性拓宽到 64 位, n) & ((1<<W)-1)`。
W<64 时「截回 W 位」把符号补回来，看起来像算术；**W=64 时截位是空操作 → 逻辑右移**。
W=8 对照：`q4f.si` `S8 -8 >> 8` = `f8`、`>> 9` = `fc`（低 8 位 = 0xF8/0xFC，也是算术）。

验证：`python tools/try_compile_dll.py --compile --src work/tmp/ul8/q1.si` → `[0]=0x31DD`（12765 = 文件大小）
      + 上面的 `cp`/`host.py`/字节命令 → `q1.pages/t0003_…bin` 的 `+264…+288`
      （`q1b`：`[0]=0x31EB`/12779；`q1c`：`[0]=0x32E7`/13031）

## Q2 移位量按**声明宽度取模**（不是「越界给 0」）

片段 `q2.si`（`let u32one = U32 1`）与 `q5b.si`、`q5c.si`：

```text
q2   +264  U64 (u32one << 32)          01 00 …      = 1   （32 & 31 = 0）
     +272  U64 (u32one << 33)          02 00 …      = 2   （33 & 31 = 1）
     +280  U64 (u32one >> 32)          01 00 …      = 1
     +288  U64 (u32one << 64)          01 00 …      = 1
q5b  +264  U64 (U8 1 << 9)             02 00 …      = 2   （9  & 7 = 1）
     +272  U64 (U8 1 << 12)            10 00 …      = 0x10（12 & 7 = 4）
     +280  U64 (U8 0xFF >> 8)          ff 00 …      = 0xFF（8 & 7 = 0）
     +288  U64 (U64 1 << 64)           01 00 …      = 1   （64 & 63 = 0）
     +296  U64 (U64 1 >> 64)           01 00 …      = 1
     +304  U64 (U32 0x80000000 >> 33)  00 00 00 40 … = 0x40000000（33 & 31 = 1）
q5c  +264  U64 (U8 0xFF >> k8)         ff 00 …      = 0xFF（k8 = 8，运行期）
```

## Q4 `asr(x, n)` 与 `x >> n`：小移位量 + W<64 才一致

一致的场合（`q4.si` 常量、`q4b.si` 运行期，`rn = S32 (cycle-11) = -8`、`k1 = 1`）：

```text
q4   +320  U64 (asr(S32 -8, S32 1))   fc ff ff ff 00 …     = -4
     +328  U64 (S32 -8 >> 1)          fc ff ff ff 00 …     = -4（相同）
q4b  +264  U64 (asr(rn, k1))          fc ff ff ff 00 …     = -4
     +272  U64 (rn >> k1)             fc ff ff ff 00 …     = -4（相同）
```

**不一致 ①：移位量 ≥ W**（`q4b`/`q4c`/`q4e`/`q4f`）

```text
q4b  +280  U64 (asr(rn, k33))   ff ff ff ff 00 …   S32 -8 asr 33 = -1（**饱和**）
q4c  +264  U64 (rn >> k33)      fc ff ff ff 00 …   S32 -8 >> 33 = -4（= `>>1`，取模）
q4c  +272  U64 (asr(rn, k65))   ff ff ff ff 00 …   asr 65 也是 -1（不是 65&31=1）
q4c  +296  U64 (asr(rn, 63))    ff ff ff ff 00 …   = -1
q4e  +264  U64 (asr(rn, k30))   ff ff ff ff 00 …   asr 30 = -1
     +272  U64 (asr(rn, k31))   ff ff ff ff 00 …   asr 31 = -1
     +280  U64 (asr(rn, k32))   ff ff ff ff 00 …   asr 32（= W）= -1 ← 不是 32&31=0 的 -8
q4f  +264  U64 (asr(S8 -8, 1))  fc 00 …            = -4
     +272  U64 (asr(S8 -8, 7))  ff 00 …            = -1
     +280  U64 (asr(S8 -8, 8))  ff 00 …            = -1 ← 不是 8&7=0
     +288  U64 (asr(S8 -8, 9))  ff 00 …            = -1 ← 不是 9&7=1 的 -4
     +296  U64 (S8 -8 >> 8)     f8 00 …            = -8（`>>` 才是取模）
```

W=32 与 W=8 的 `asr` 都在 `n = W` 处**饱和**（给全符号位），**不取模**。

**不一致 ②：W=64**（`q4b`/`q4c`/`q4e`）

```text
q4b  +288  U64 (asr(rz, k1))    fc ff ff ff ff ff ff ff    S64 -8 asr 1 = **-4**（算术）
     +296  U64 (rz >> k1)       fc ff ff ff ff ff ff 7f    S64 -8 >> 1 = **0x7FFF…FFFC**（逻辑）
q4c  +280  U64 (rz >> k65)      fc ff ff ff ff ff ff 7f    `>>65` ≡ `>>1`（65 & 63）
     +288  U64 (asr(rz, k65))   fc ff ff ff ff ff ff ff    `asr65` ≡ `asr1` → W=64 **不饱和**，走 `&63`
q4e  +288  U64 (asr(rz, k32))   ff ff ff ff ff ff ff ff    asr 32 = -1（正常）
     +296  U64 (asr(rz, k64))   f8 ff ff ff ff ff ff ff    asr 64 ≡ asr 0 = -8 ← 取模，不饱和
```

**`asr` 无视操作数的符号声明**（`q4c`）：`asr(U32 0x80000000, 1)` = `00 00 00 c0 …`（0xC0000000，按 W 位符号位补），
而同一个 `U32 0x80000000 >> 1` = `0x40000000`（Q1 +280）。`asr(U32 0xFFFFFFF8, 1)` = `00 00 00 fc …` = -4 同款。

验证：`python tools/try_compile_dll.py --compile --src work/tmp/ul8/q4b.si` → `[0]=0x34B0`（13488）
      + `cp`/`host.py`/字节命令看 `q4b.pages/t0003` 的 `+264…+296`
      （`q4`：`[0]=0x31DD`/12765；`q4c`：`[0]=0x34C6`/13510；`q4e`：`[0]=0x35DC`/13788；`q4f`：`[0]=0x3646`/13894）

## Q5 `U8 1 << 8` = `1`（被声明宽度截断 + 移位量取模）

片段 `q5.si`（`let b1 = U8 1`、`let bff = U8 0xFF`）：

```text
+264  U64 (b1 << 7)          80 00 …      = 0x80
+272  U64 (b1 << 8)          01 00 …      = **1**  ← 既不是 0，也不是 0x100
+280  U64 (U8 (b1 << 8))     01 00 …      = 1
+288  U64 (bff << 4)         f0 00 …      = 0xF0 ← 结果**确实截到声明宽度**（0xFF << 4 = 0xFF0 → 0xF0）
+296  U64 (U16 (b1 << 8))    01 00 …      = 1    ← 移位本身已在 U8 域里丢了 0x100
```

→ 两件事叠加：移位量 `8 & (8-1) = 0`（所以是 `1 << 0`），结果再截到 U8 的 `(1<<8)-1`。
`U8 1 << 7 = 0x80` 正常（没溢出到 9 位）。

## 未解 / 越界（不算 U-L8 的结论，别当已定）

1. **`/`、`%` 的符号性（非零除数）测出来是不一致的，机制未定**（超出五问，但直接威胁 `/` 的保真）：
   同一个 `-7 / 2`：

   | 片段 | 分子构造 | 分母构造 | `-7 / 2` 实测 |
   |---|---|---|---|
   | `q1d` | `S32 (cycle - 10)` | `S32 (cycle - 1)` | `0xFFFFFFFFFFFFFFFD` = **-3** |
   | `q3h` | `S32 0 - S32 7` | `S32 2` | `0x00000000FFFFFFFD` = **-3** |
   | `q3g` | `S32 0 - S32 7` | `S32 cycle - S32 1` | `0x000000007FFFFFFC` = **+2147483644** |
   | `q3i` | `S32 0 - S32 7` | `S32 2` | `0x000000007FFFFFFC` = **+2147483644** |

   关键点：`q3h` 与 `q3i` 的**两行构造文本完全相同**（`let a = S32 0 - S32 7` + `let p = S32 2` + `a / p`），
   却一个走有符号、一个走无符号 → 不是「按声明的符号性选 `sdiv`/`udiv`」那么简单，也不是我拟合出的任何
   统一规则（试过：分子标签决定 / 分母标签决定 / 两者取或 / 按分母符号位分支，都被上表或
   `q3g` 的 `-7 / -2 = 3`（有符号）与 `-7 % -2 = -1`（有符号）打掉）。
   `INT_MIN` 档同一现象：`q3f`（`imin = S32 2147483647 + S32 1`、`p2 = S32 cycle - S32 1`）
   `imin / 2` = `+1073741824`、`imin / -2` = `+1073741824`、`imin / -1` = `0x80000000`、`imin % -1` = 0；
   `q3c`（`S32 0x80000000` 字面量）/`q3d`/`q3e`（`S32 (U32 0x80000000 + …)`）构造时 `imin / -1` 得 0。
   全部不 trap（3 tick 全绿）。余数能用 `r = a - b*q` 讲通（含 `7%0 = 7`、`-7%0 = -7`），
   但 `q` 本身无模型。**待单独一线查（更像类型/标签问题，属 U-L7 邻近）**，不要当已定。
2. **窄有符号「变量」加宽是零扩展、常量/表达式加宽是符号扩展**（`q1d.si`）：
   `U64 rn`（`rn = S32 (cycle-11)`，运行期 -8）= `0x00000000FFFFFFF8`；`U64 (S64 rn)` 同样零扩展；
   同一片段里 `U64 (S32 -8)`（常量）与 `U64 (S32 (cycle - cycle - 8))`（运行期表达式）= 全 FF（符号扩展）。
   `docs/facts.md` §U-L7 第 3 条是用**常量**测的，对它成立；「运行期窄变量」这一路与它不一致。
   这是 **U-L7/U-L1 的遗留**，本任务不碰，交主程裁定要不要回头补。
3. 没测：`asr` 在 W=16 的饱和点；`>>`/`asr` 在 W>64；`/` 与 `%` 对 `U64/S16/S8` 等其它宽度；
   `clz/ctz/rol/ror`（不属 U-L8）；除零时参考实现是否改 `#SIMULATION_STATE` 的错误字段（没查 UI 面）。

## 对 lowering 的直接指示

1. **`>>` 必须按 W 发指令，不能只按符号性选 `lshr`/`ashr`**：
   用统一配方 `trunc(lshr(sext/zext_64(x), n_masked), W)` 复刻（`zext` 对无符号、`sext` 对有符号），
   这样 W<64 自动得算术、**W=64 自动得逻辑** —— 千万别对 `S64/Int` 发 `ashr i64`（参考实现是逻辑右移）。
2. **移位量先 `and (W-1)` 再进 LLVM 移位**：`shl/lshr/ashr` 的越界移位量在 LLVM 是 `poison`，
   而参考实现有定义（硬件式取模），所以掩码必须显式生成（W=8/32/64 都实测过）。
3. **`asr` 单独 lowering，不要拿它当 `>>`**：按 W 位符号位算术右移（**无论操作数声明有无符号**），
   移位量 W<64 时 `min(n, W-1)`（饱和）、W=64 时 `and 63`（取模）；结果按 W 位掩码。
4. **除法/取模不许发裸 `sdiv/udiv/srem/urem`**（零除数与 INT_MIN 边界在 x86/LLVM 上是 trap/poison，
   参考实现不 trap）：零除数那一档实测语义是 `b == 0 → q = 0、r = a`（三种构造一致，可直接照抄）；

   并把「除法的符号性」挂成独立待办。
